## 1. 验收使用原则

- 本文件的 AC 是 **V1 核心端到端验收场景**，不是对全部 FR 的逐条测试用例全集。
- 每个实现任务应引用对应 FR；测试用例可在核心 AC 基础上继续细化边界、异常和平台兼容场景。
- 如 AC 与 FR 描述不一致，应先修正规格，不应由测试阶段自行改变产品语义。
- V1 首发验收平台为 macOS；最低系统版本及 CPU 架构覆盖仍待打包确认。2026-10-08 的 [CLI 开发前校验](<06. CLI Integration Preflight.md>)提供 Adapter 实现输入，不替代本文件的端到端验收。


## 2. V1 核心验收场景

### AC-01 多项目

用户同时打开三个本地项目。

能够通过顶部 Project Tabs 快速切换。

三个 Project 的：

- Session；
- Project View；
- Context Panel 状态；

保持独立。

---

### AC-02 创建 Codex Session

用户在 Project A 创建 Codex New Chat。

输入需求后：

- Codex 正常开始执行；
- Session 出现在左侧；
- 显示 Running；
- Conversation 流式输出。

---

### AC-03 并发执行

用户在同一 Project 创建：

- 一个 Codex Session；
- 一个 Claude Code Session。

两个 Session 可以同时执行。

切换 Session 不应打断后台执行。

---

### AC-04 完成提醒

用户正在 Session B。

Session A 在后台完成。

结果：

- Session A 出现绿色圆点；
- 用户点击 Session A；
- 页面直接显示最新 Conversation；
- 绿色圆点消失。

---

### AC-05 Needs Input

后台 Agent 需要用户做决定。

Session History 中必须出现明显 Needs Input 状态。

用户点击后可以直接看到 Agent 当前等待内容。

---

### AC-06 Project View

用户打开 Architecture。

页面显示：

- 左侧 Conversation；
- 右侧 Architecture Preview。

用户输入：

“重新整理支付模块架构。”

系统可以通过普通 CLI Session 处理请求，并更新 Architecture Preview。

---

### AC-07 工具面板

用户可以分别打开：

- Files；
- Diff；
- Browser；
- Terminal。

关闭后 Main Canvas 恢复空间。

Agent 不得自行强制打开这些 Panel。

## 4. 当前验收覆盖边界

现有 AC 聚焦产品最核心的端到端闭环。以下内容仍应在测试设计阶段依据 FR/NFR 补充专项测试：Session Resume、Rename、Model Selector、错误恢复、大量 Session 性能、多 Project 后台运行、Project Knowledge / View 数据分离、Browser/Terminal 边界、CLI Adapter 状态映射、本地持久化，以及原型阶段补充的 New Chat 草稿、Needs Input / Error 清除规则、Project Tab 注意力点和关闭 Project 确认（见 UX Specification 第 10 节）等。该列表用于测试规划，不改变其 P0/P1 定义。

Stop 专项测试应依据 FR-INPUT-001、FR-SESSION-003、FR-PROJ-002 和 Technical Requirements 第 4 节覆盖：本轮命令归属与退出、先前后台服务的清理范围、其他 Session / 用户 Terminal 隔离、重复 Stop / 迟到事件、实验接口不可用或清理失败后的 Runtime 兜底，以及原 Session ID / 上下文恢复。2026-10-08 的原生 Stop 复核已提供接口层证据，见 [CLI Integration Preflight](<06. CLI Integration Preflight.md>) 第 4、5 节；上述产品与异常场景仍待端到端验收，不能将接口检查通过视为 AC-03 或全部 Stop 行为已验收。
