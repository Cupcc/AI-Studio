# W2: where the packaged smoke wrote its data (paths sanitized: <tmp>, ~)

## Finding: apps/desktop/scripts/packaged-smoke.mjs (line 42) passes only --studio-smoke-output.
Without --studio-user-data-dir a packaged app uses app.getPath('userData')
(~/Library/Application Support/AI Developer Studio), so `pnpm smoke:packaged` as shipped writes
studio.sqlite3 (app_meta key smoke.lastRun) and Chromium profile directories (Cache, Code Cache,
GPUCache, Local State, ...) into the real user's application data. W1 reported the same side effect.
The override switch exists (apps/desktop/src/main/launch-options.ts), the script just does not use it.

## What W2 ran instead
A verbatim copy of packaged-smoke.mjs kept outside the repository, with one added argument:

42c42
< ... '--args', `--studio-smoke-output=${outPath}`], {
---
> ... '--args', `--studio-smoke-output=${outPath}`, `--studio-user-data-dir=<tmp>/smoke userdata`], {

Same launch environment (PATH=/usr/bin:/bin:/usr/sbin:/sbin, HOME/USER/LOGNAME/TMPDIR only), same
`/usr/bin/open -n -W <app> --args ...` call. The unmodified `pnpm smoke:packaged` was deliberately
not run, to avoid touching the real application data again.
