## 规则

- 跨模块产品取舍、技术选择及 [04 第 1 节](<04. Technical Requirements.md>)落定的事项记在此处。原型交互决定由 [03 第 10 节](<03. UX Specification.md>)维护，不重复记录。
- 每条保留结论、理由和来源。行为细节由 spec 负责，实施与验收状态由任务记录负责。
- `DEC-NN` 递增且不复用。状态为草稿、已确认或已废弃，确认须注明日期，废弃须指向替代决定。
- 决定被推翻时新增一条，并把原条目标为已废弃，保留原结论与替代关系。
- 本文的确认指决策确认，不代表实现完成或产品验收。文档 diff 按[文档索引](<00. Documentation Index.md#文档规则>)审阅。

## 桌面端基础

### DEC-01 SQLite 驱动采用 `node:sqlite`

草稿 · 2026-10-09 · [骨架调研 §3](../tasks/archive/T20261009-app-skeleton/research.md)

主进程使用内置 `node:sqlite`，避免 `better-sqlite3` 在 Electron 与 Vitest 的不同 Node ABI 下重复编译。内置驱动已通过当时的主进程与打包冒烟验证。

数据库放在 userData，通过 `CoreServices` 访问，迁移只向前且幂等。位置与用法见[桌面端运行时约定](../apps/desktop/README.md#4-运行时约定)。升级 Electron 时复跑数据库测试。

### DEC-02 进程边界与类型化 IPC

草稿 · 2026-10-09 · [骨架调研 §2、§5](../tasks/archive/T20261009-app-skeleton/research.md)；安全例外于 2026-10-10、10-13、10-14 确认

应用窗口启用 `contextIsolation`、`sandbox` 和 CSP。Renderer 通过类型化 IPC 调用主进程，Preload 按契约生成桥接，主进程先校验输入。采用集中登记，避免手写桥接与契约不一致；不提供任意通道的 `invoke(channel)`，也不引入 tRPC。

应用默认拒绝新窗口、外部导航、`webview` 和权限请求。保留以下例外：

- http / https 新窗口请求交给系统浏览器；应用 Renderer 可写入剪贴板，用于复制代码块。依据见 [Markdown 渲染任务](../tasks/archive/T20261010-prototype-v02-alignment/task.md)。
- Browser 预览使用独立 WebContentsView，不加载应用 Preload，自行处理导航、权限和下载。
- xterm 依赖运行时样式和内联属性，CSP 对 `style-src-elem`、`style-src-attr` 允许 `'unsafe-inline'`；脚本与外部资源限制不变。用户分别于 2026-10-13、10-14 接受该取舍。

IPC 用法见[桌面端说明 §3](../apps/desktop/README.md#3-新增一个-ipc-功能)，Browser 隔离与 xterm 样式验证见[工具规格 §5.1](../specs/tools/spec.md#51-运行时实现细化)。

### DEC-03 功能目录与写入范围

草稿 · 2026-10-09 · [桌面端目录](../apps/desktop/README.md#2-目录)

按功能组织契约、处理器、服务与 Renderer 目录，功能间不直接引用对方内部文件。共享登记文件每个功能只加一行，骨架修改在任务中说明。这样可按功能路径划分并行任务的写入范围。

## Project View

DEC-04～07 于 2026-10-09 确认，来源为 [Project View 任务](../tasks/archive/T20261009-project-view/task.md)的 Q1～Q12。行为细节见 [Project View 规格](../specs/project-view/spec.md)。

### DEC-04 Project Knowledge 存储

已确认（2026-10-09） · Q1、Q2、Q6、Q11

默认五个 View 的 Knowledge 与 View Definition 存在 Project 的 `.ai-studio/`，每个 View 使用独立、带 `schemaVersion` 的 JSON 文件。目录默认被 Git 忽略；客户端读取和校验 Knowledge，不修改内容。

Agent 可直接通过 CLI 文件工具更新，无需额外写入工具或项目外权限。分文件减少并行 Session 的写入冲突；存储格式与路径由规格维护。

### DEC-05 Project View 渲染

已确认（2026-10-09） · Q3、Q4、Q5

默认五个 View 使用经 Schema 校验的声明式 JSON。Agent 在该入口只能选择受信组件、布局和数据绑定；失败时保留上次成功版本并提示错误。自定义工作台采用独立的 Web 页面入口，功能优先的推进顺序见 DEC-28（2026-11-10 对话调整，diff 待审阅）。

这使事实与展示分离，并限制 Agent 输出的执行能力，代价是 View 设计受组件范围约束。自定义工作台的容器与接口按 DEC-28 先设计、随实现检查，不复用默认 View 的声明式入口执行脚本。

### DEC-06 View Context 注入

已确认（2026-10-09） · Q7、Q8、Q10、Q12

从默认 View 发起的首条消息附加独立英文文本块，包含当前 View、文件路径和少量编辑规则，不内联 Knowledge。Codex 与 Claude 使用同一文本；用户可移除"当前 View"标签，移除后不注入，但保留 `origin_view_id`。

选择可见、可移除的消息上下文，避免修改用户的 AGENTS.md / CLAUDE.md。默认 View 不使用隐藏的系统提示、打包 Skill 或 Claude hooks 注入。工作台每次发送的上下文按 FR-WB-003 处理。

### DEC-07 Project View 刷新与权限

已确认（2026-10-09） · Q9

客户端不自动发起 AI 生成。Project 打开期间监视 `.ai-studio/`，并在打开 Project、回合结束、窗口聚焦时补扫，校验通过后刷新默认 View 的只读 Preview。刷新不切换当前内容，多步更新的中间错误延后提示。

这样可及时呈现 Agent 的文件修改，同时遵守不自动生成、无隐藏对话和失败保留上次成功渲染的要求。
