## 2. 职责与边界

- 负责：设置入口与对话框；外观偏好（毛玻璃背景颜色、颜色模式）的读取、保存与广播；根据偏好与系统状态（深浅色、“降低透明度”）计算实际外观并应用到所有窗口；应用级默认 CLI 的选择入口。
- 不负责：各功能自身的配色（由 Token 统一提供）；CLI 可用性检测与会话生命周期（由 chat / session 模块负责）；导航折叠等既有偏好；自定义颜色或图片背景。

## 3. 行为细则

### FR-SET-001 设置入口

1. 入口：
   - 左侧导航底部固定“设置”行（SET-Q1）；
   - 菜单栏应用菜单“设置…”，快捷键 ⌘,；启动页、导航折叠时同样可用（SET-Q2）。
2. 设置对话框：
   - 模态，居中，宽 640、高 520，窗口较小时不超出窗口；标题“设置”，右上角关闭按钮。
   - 左列分类：默认选中“外观”；另有“CLI”分类用于应用级默认 CLI。外观右列依次为“模式”“毛玻璃背景”。
   - 已打开时再次触发入口不重复打开。
   - 关闭：关闭按钮、Esc、点击对话框外（SET-Q3）；关闭后焦点回到打开前的元素。
   - 打开时焦点在当前选中的模式上；每个单选组一个 Tab 停留点，Tab 焦点限制在对话框内。
3. 其他对话框（关闭 Project、退出确认）显示时，设置入口不响应。

### FR-SET-002 外观主题

1. 模式（SET-C7）：“跟随系统”（默认）、“浅色”、“深色”，分段单选组。跟随系统时，系统切换深浅色后应用立即跟随，无需重启。
2. 主题：不提供选择（SET-C9）。界面为毛玻璃；“纯色”（SET-Q6）只作第 5 条的系统回退。两种外观在两种模式下都有对应取值（SET-Q7）。
3. 模式与毛玻璃背景选择后立即保存并应用到所有窗口：
   - Renderer 切换 `<html>` 的外观属性；
   - 主进程设置或移除窗口材质与底色，并更新原生 UI 的深浅色。
   - 不改变 Project、Session、草稿、布局与滚动位置；对话框保持打开。
4. 实际主题 = 系统未开启“降低透明度”时为毛玻璃，否则为纯色；深浅色由模式决定。
5. 系统开启“降低透明度”：
   - “毛玻璃背景”下方提示“系统已开启“降低透明度”，当前显示为纯色外观。”；背景颜色仍可选择并保存，系统选项关闭后生效；
   - 系统选项变化时实时更新，无需重启。
6. 毛玻璃背景颜色（SET-C6、SET-Q5）：“模式”下方始终显示“毛玻璃背景”单选组；点选立即生效、应用级保存。系统开启“降低透明度”时窗口不显示背景颜色，但保留所选颜色。深色模式下各颜色为同色相的深色渐变。
7. 保存失败时：保持原外观，在设置中显示“未能保存外观设置”；不重试。
8. 启动：主进程读取偏好、应用模式并以对应外观创建窗口；Renderer 在首次渲染前应用外观。
9. macOS 运行中的 Dock 图标按实际颜色模式使用浅色 / 深色版本（SET-C8），适用于开发和打包应用。手动选浅色 / 深色立即切换；跟随系统时响应系统深浅色变化；启动时应用已保存的模式。毛玻璃背景颜色和“降低透明度”不改变图标的颜色模式。未运行应用的 Finder / 应用包图标仍使用打包的浅色版本。

### CLI 连接配置（2026-11-08 确认）

用户在机制研究后回复「apply,实现上述方案」（2026-11-08 确认）。应用为每个 CLI 保存独立连接配置：默认使用本机配置；选择应用配置时提供 Base URL、API Key 与可选的测试模型，使用系统密钥保护能力保存 API Key。2026-11-10 用户明确要求移除 model，其他设置沿用本机配置；后续补充要求测试直接调用 API，并参考 Cockpit Tools 的唤醒。应用不修改 `~/.codex`、`~/.claude` 等本机配置文件，也不在退出时还原文件。

1. Codex 读取原生有效 provider 的传输选项后，通过 app-server 启动参数覆盖连接地址与密钥来源；Claude Code 覆盖 endpoint / credential。应用不再覆盖连接级 model，模型目录沿用 CLI 原生目录；历史连接记录中的 model 在读取时忽略。Skills、MCP、Hook、权限等未明确覆盖的原生配置继续由 CLI 读取。
2. 连接配置变更后，新建 Session 使用新配置；已有 Session 保存配置修订快照，继续使用创建时的配置。重启应用不改变已保存 Session 的快照。
3. API Key 不经 Renderer 返回，不写入普通配置或日志。系统密钥保护不可用时保存失败，不回退为明文。界面只展示“已安全保存”状态；更换地址时须重新输入密钥。
4. “测试连接”只检查网关与 API 是否可达：使用已保存的应用连接，直接调用 Responses / Messages API 发送 `hi`，不启动 CLI，也不创建 Session。模型取连接中填写的“测试模型”，未填写时用应用内置的默认模型（Codex `gpt-6.1-sol`、Claude Code `claude-opus-5-5`，取各 CLI 当前版本的默认模型），模型名原样发送，不解析别名（用户 2026-11-13 决定）。测试模型只用于测试，不影响 Session 使用的模型。只有完整响应含可读回复才显示通过，并展示模型、耗时与回复；HTTP 错误、流失败、截断、空回复及超时均不通过，不自动重试。失败提示区分 Key 被拒（401 / 403）、额度或限流（402 / 429）、模型不可用（错误内容表明模型不存在或无可用渠道）与其他错误，不回显响应原文。测试不代表 CLI 端到端可用。保存配置本身不发送模型请求。
5. 应用配置只覆盖已定义的连接字段，不提供任意 CLI 参数注入；Base URL 接受 HTTP 与 HTTPS，不另作明文提示（用户 2026-11-13 决定）。
6. 依据用户 2026-11-10「UI 太丑了，重新设计」：点击配置进入独立连接详情页，保留设置分类导航；以分段选择切换本机配置 / 自定义连接，表单含 URL、Key 与可选的测试模型（占位文字显示默认模型）。底部固定取消 / 保存，保存后留在详情页；有未保存修改时禁用测试并说明原因。测试结果独立展示状态、模型、耗时与回复，完成后滚动至结果。返回列表或取消会丢弃未保存修改。

### CLI 管理与默认 CLI（2026-10-25 确认）

用户提出固定右上检测与按启用范围检测，并回复「是这个意思」；随后明确纠正分组为「上方是已经添加的，下方是没有添加的。上分用户点击就是选中为默认」（2026-10-25 确认，文档 diff 待审阅）。以下按后一次纠正，不采用先前“管理 / 默认”两个重复列表。

本节的界面文案遵循 [UX Specification §8.1“文字与信息层级”](<../../docs/03. UX Specification.md#文字与信息层级>)：行为由行结构、选中态、默认勾选、检测状态和必要的短暂反馈表达，不在列表旁重复显示“点选后立即生效”“所有 Project 共用”等常驻说明。

1. “CLI”内容区有固定标题栏，右上为“重新检测”；下方内容独立滚动，列表增长不改变按钮位置。上方“已添加”、下方“未添加”，紧凑行展示；组内按固定 Provider 顺序，添加 / 移除时跨组移动。
2. 已添加行展示名称与检测状态，点击可用行即设为默认，默认项前方打勾，其余行保留对齐占位；右侧可“移除”。未添加行提供“添加”，点击后移到上方待检测。已添加表示启用，不等于检测可用；检测失败行提供“处理方法”。未添加项不出现在普通 / Project View 新建对话选择器中。
3. 已添加列表应用级保存、跨项目与重启共享。初次引入该偏好时保留当前已支持 CLI，不要求原用户重新配置；之后新增支持项默认未添加。手动检测与日常可用性检查只启动已添加项的检查，全部移除时检测按钮禁用；新添加项显示待检测，移除后迟到的检测结果不得重新添加它。
4. 不再重复单独的默认组。已添加且可用的项允许设为默认，一个可用项自动采用。显式默认不可用 / 被移除时采用第一个已添加可用项，没有则为无可用 CLI；可用性恢复时仍尊重保存的默认偏好。默认和已添加列表应用于所有 Project。
5. 改默认不覆盖已有明确选择的草稿；取消草稿所选 CLI 时切换到可用默认（无则清空 CLI），重置模型 / effort，保留文字与附件。取消启用只限制新建会话，不终止正在运行的会话、不隐藏历史，也不禁止已有 Session 续聊。
6. 保存失败保留原设置并显示错误；添加 / 移除后焦点跟随对应行的新操作，默认选择支持方向键，Tab 限制在对话框内。没有可用 CLI 时 Composer 提供“CLI 设置”入口及可用替代项，不只显示提示。

## 4. 状态与数据

```ts
type Theme = 'glass' | 'solid'                                     // 实际外观，用户不选择（SET-C9）
type GlassColor = 'aurora' | 'mint' | 'sunset' | 'haze' | 'none'   // SET-Q5
type ColorMode = 'system' | 'light' | 'dark'                       // SET-C7
interface AppearanceState {
  glassColor: GlassColor          // 毛玻璃背景颜色；默认 'aurora'
  mode: ColorMode                 // 颜色模式；默认 'system'
  reducedTransparency: boolean    // 系统“降低透明度”
  dark: boolean                   // 当前使用深色（强制深色，或跟随系统且系统为深色）
  effective: Theme               // 实际主题，见 FR-SET-002 第 4 条
}
```

- 持久化：`app_meta`（SET-T3），应用级，所有窗口共用。
- Renderer：设置 store 保存 `AppearanceState` 与对话框开关；`<html>` 的 `data-theme` 取 `effective`，`data-scheme` 取 `dark`，`data-glass-color` 取 `glassColor`。

## 5. 接口与事件

IPC 契约 `settings`（[DEC-02](<../../docs/07. Decisions.md#dec-02-进程边界与类型化-ipc>)）：

| 成员 | 类型 | 说明 |
|---|---|---|
| `getAppearance` | invoke `void → AppearanceState` | 当前状态 |
| `setGlassColor` | invoke `{ color } → AppearanceState` | 校验取值后保存毛玻璃背景颜色并应用；外观变化时广播 `appearanceChanged` |
| `setMode` | invoke `{ mode } → AppearanceState` | 同上，保存颜色模式并写入 `nativeTheme.themeSource` |
| `appearanceChanged` | event `AppearanceState` | 偏好或系统状态（深浅色、“降低透明度”）变化时发送给所有窗口 |
| `openRequested` | event `void` | 菜单栏“设置…” / ⌘, 触发，Renderer 打开对话框 |
