## 3. 总体页面结构

客户端采用四个主要区域：

1. 顶部 Project Tab Bar；
2. 左侧 Project Navigation / Session History；
3. 中央 Main Canvas；
4. 右侧可折叠 Context Panel。

基本结构：

```text
┌───────────────────────────────────────────────────────────────┐
│ Project A × │ Project B × │ Project C × │ +                  │
├──────────────┬─────────────────────────────────┬──────────────┤
│              │                                 │              │
│ Project View │                                 │ Files        │
│ Navigation   │                                 │ Diff         │
│              │          Main Canvas            │ Browser      │
│──────────────│                                 │ Terminal     │
│              │                                 │              │
│ Sessions     │                                 │              │
│              │                                 │              │
└──────────────┴─────────────────────────────────┴──────────────┘
```

右侧 Context Panel 默认允许收起。

顶栏（Project Tab Bar）左侧放置左侧导航折叠按钮，右端放置右侧边栏（Context Panel）按钮。

## 4. Project View 交互模型

Project View Mode 的权威功能要求位于 **FR-VIEW-005 ~ FR-VIEW-008**。设计实现必须满足以下已确认约束：

- Main Canvas 使用 **左 Conversation、右 Project View Preview** 的左右结构；
- Conversation 保持完整纵向空间，Preview 保留足够二维展示空间；
- Project View 左侧对话仍是普通 CLI Session，不创建特殊 Project Chat；
- 从 Project View 创建 New Chat 时，新 Session 同步进入 Session History；
- 一个 Project View 不永久绑定唯一 Session；
- 用户可以在描述修改需求的同时观察 Preview 更新。

```text
┌──────────────────────┬──────────────────────────┐
│                      │                          │
│    Conversation      │      View Preview        │
│                      │                          │
│                      │                          │
│                      │                          │
│ ┌──────────────────┐ │                          │
│ │ Input            │ │                          │
│ │ Model          ↑ │ │                          │
│ └──────────────────┘ │                          │
└──────────────────────┴──────────────────────────┘
```

## 5. Context Panel 交互模型

- Context Panel 支持展开/收起；
- Files / Diff / Browser / Terminal 由用户主动打开和切换；
- AI 不因执行任务自动弹出、切换或改变这些工具；
- Workspace 布局保持稳定、可预测；
- 工具面板不得抢占 Main Canvas 的主视觉层级；
- 入口为顶栏右端的单一右侧边栏按钮；展开后默认显示该 Project 上次选择的工具（P-C）；
- 面板顶部以图标切换 Files / Diff / Browser / Terminal，悬停显示名称；同一时间只显示一个工具；
- 点击右侧边栏按钮或面板关闭按钮即收起；
- 宽度可拖拽调整，并按 Project 记忆；
- Project View Mode 下，工具与 Preview 共享右侧区域：区域顶部以图标在 Preview 与四类工具之间切换，打开工具即替换 Preview，三列布局不变；点击 Preview 图标或右侧边栏按钮回到 Preview（P-B）。

Diff 与 Terminal 的内容交互补充（2026-10-10 确认；FR-TOOL-002、FR-TOOL-004）：

- 从工具入口打开 Diff 时查看“项目变更”；从 Conversation 轮次完成行进入时查看该轮的“本轮变更”，标题标明范围及关联轮次，不静默切换数据来源。
- 本轮记录不可用时，显示“本轮变更不可用”及“查看项目变更”入口；非 Git 的项目变更显示说明和 Git 初始化指引。数据边界见 FR-TOOL-002。
- Terminal 内部用 Tab 切换实例，提供新建和关闭入口；同一时间仍只显示一个工具、一个终端实例的内容。收起工具面板与关闭 Terminal Tab 是不同操作，收起面板保留进程和输出。
- 组件结构见 [Shell Spec v02](../design/components/shell-spec-v02.md) 第 6、9 节。


## 6. 页面行为

### 启动页与新增 Project

- 没有打开任何 Project 时显示启动页：“打开本地目录”与最近打开的 Projects；
- Project Tab Bar 的 `+` 在新 Tab 中打开同一启动页；
- 选择的目录已经打开时，切换到对应 Tab（FR-PROJ-001）。

---

### New Chat

1. New Chat 位于左侧导航顶部，主按钮使用 Project Default CLI；
2. 右侧下拉菜单列出 Codex CLI 与 Claude Code CLI，并提供“设为此 Project 默认”；
3. 新 Project 的 Default CLI 沿用最近一次设置的默认值；首次使用时为检测到的第一个可用 CLI；
4. 未安装或未登录的 CLI 在菜单中禁用，并说明原因；
5. 点击后进入新对话草稿，发送第一条消息时创建 Session（FR-CHAT-001）。

---

### Session 打开

用户点击一个 Session：

1. 清除其 Completed Unread 或 Error 提醒；
2. Main Canvas 切换为 Conversation Mode；
3. Conversation 直接显示最底部；
4. 输入区可立即继续输入。

如该 Session 创建于某个 Project View，Conversation 顶栏显示来源 View，并提供“在 View 中打开”入口。

---

### Project View 打开

用户点击一个 Project View：

1. Main Canvas 切换为 Project View Mode；
2. 左侧 Conversation；
3. 右侧 Preview；
4. 用户可以继续使用已有 Session 或创建 New Chat；
5. 当前 View 作为 Session Context 的一部分。

从左侧导航进入 View 时，左侧 Conversation 为新对话草稿，不创建 Session；草稿上方列出该 View 最近的对话，点击即可继续（P-A）。继续某个对话后，Conversation 顶栏显示 Session 标题，并提供新建对话按钮。

切换 Project Tab 后返回时，按 FR-PROJ-003 恢复离开时的完整状态，包括正在显示的对话；新草稿规则只用于从导航进入 View。

---

### Project 切换

用户点击顶部其他 Project：

- 切换整个 Workspace Context；
- 恢复该 Project 上一次状态；
- 不停止其他 Project 中已经运行的 Session。

---

### Project 关闭

关闭 Tab 时，如该 Project 仍有 Running 或 Needs Input 的 Session，显示确认对话框，说明受影响的 Session 数量；确认后停止这些 Session 的当前一轮（FR-PROJ-002）。没有此类 Session 时直接关闭。

---

### Needs Input 与 Error 呈现

- Needs Input：在 Conversation 末尾显示等待卡片，内容为 CLI 原生的问题和选项（如允许 / 拒绝、选项列表），按钮直接回传给 CLI；输入框保持可用，用户也可以直接输入回复。打开 Session 时位于最底部，可立即看到等待内容（AC-05）。
- Error：在 Conversation 末尾显示错误卡片，包含错误摘要和“重试”，错误详情可展开查看。

---

### Project View 空状态与更新

- Project Knowledge 尚未生成时，Preview 显示空状态和“生成 <View 名称>”入口；点击后把可编辑的生成指令填入左侧输入框，由用户发送（FR-VIEW-003）；
- Overview 中的 Recent Sessions、Needs Input、Recently Completed 来自客户端 Session 数据，Knowledge 为空时也直接显示；
- Preview 只读，支持滚动与缩放，修改通过 Conversation 完成；
- Agent 更新 Knowledge 或 View 后 Preview 自动刷新，并显示“已更新”时间；刷新不改变 Workspace 布局；
- 渲染失败时保留上一次成功渲染的版本，并显示错误提示。

## 7. 状态视觉规则

V1 状态色应尽量克制。

建议：

| 状态 | 建议表现 | 清除时机 |
|---|---|---|
| Running | 中性色 Spinner / 动态点 | 当前一轮结束 |
| Needs Input | 黄色/橙色小状态点 | 用户作出答复（FR-STATE-002） |
| Completed Unread | 绿色圆点 | 用户点击查看该 Session（FR-STATE-005） |
| Error | 红色状态点 | 用户点击查看该 Session（FR-STATE-003） |
| Normal History | 无任何状态 | — |

原则：

- 不大面积使用状态色；
- 状态主要用于 Attention；
- 无事件时不增加视觉元素。

### Project Tab 注意力点

- 非当前 Project 的 Tab 显示该 Project 中优先级最高的一个注意力状态：Needs Input > Error > Completed Unread；
- 只显示一个点，不显示数量，不显示 Running；
- 当前 Project 的 Tab 不显示，相关状态已在左侧 Session History 中可见；
- 该提示只用于发现后台 Project 需要关注，不提供跨 Project 的统一列表（跨 Project Attention Inbox 为 V1 非目标）。

## 8. UI 设计要求

### 整体视觉

要求：

- 白色背景为主；
- 中性色体系；
- 少量状态色；
- 大面积留白；
- 边界弱化；
- 不使用密集 Toolbar；
- 不设计大型 Dashboard Chrome；
- 不采用传统 IDE 的深色高密度布局。

---

### 左侧导航

要求：

- 宽度稳定；
- Project Views 与 Sessions 有明显层级；
- Session History 可持续增长；
- Selected 状态明确；
- Hover 状态克制；
- Session 状态点不影响标题阅读；
- New Chat 位于导航顶部，其下依次为 Project Views 与 Session History；
- Session History 按日期分组（今天 / 昨天 / 过去 7 天 / 更早），排序规则见 FR-NAV-003；
- Session 列表项为：CLI 单色标识（CX / CC）+ 标题 + 右侧状态点（P-D）；
- 左侧导航可折叠：折叠按钮位于顶栏左侧、窗口控制按钮之后，位置参考 ChatGPT；折叠后导航完全隐藏，顶栏保留展开按钮与 New Chat 按钮；
- 折叠时如当前 Project 存在 Needs Input、Error 或 Completed Unread Session，展开按钮显示单个状态点，优先级同 Project Tab 注意力点；
- 折叠状态为窗口级偏好，切换 Project 时保持不变；
- 悬停列表项时显示“⋯”菜单，Rename 从菜单触发并在原位编辑；
- Project View Mode 下只高亮当前 View，左侧 Conversation 所用的 Session 不在 Session History 中重复高亮。

---

### Main Canvas

Session Mode：

以 Conversation 为绝对主体。

Project View Mode：

Conversation 与 Preview 左右并列。

布局比例在 UI 高保真阶段确定。

---

### Context Panel

要求：

- 支持展开/收起；
- Files / Diff / Browser / Terminal 统一入口；
- 用户手动切换；
- 不抢占 Main Canvas 主视觉层级。
