## 目标

用户 2026-11-12 参照 DeepSeek Harness 的侧栏入口审查工作台列表，指出三个现象：添加菜单里“选品工作台”多一行小字；添加后列表同时出现实例和“选品工作台草稿”；移除后的项只有“恢复”、没有“删除”。用户要求按设计问题系统审查，不做单点修复。

## 审查结论

三个现象来自同一个缺口：列表直接暴露了存储里的草稿记录、实例记录和隐藏标记，没有统一的“新建 → 预览 → 添加 → 使用 → 编辑 → 移除 / 删除”生命周期。

| 现象 | 根因 | 处理 |
|---|---|---|
| 选品有第二行说明 | 添加浮层混放新建动作、虚拟预设、走草稿的模板和恢复项，各用一种行样式；选品其实是模板，行为与同组预设不同，只好加说明 | App 模板直接添加为实例；浮层分三组，同组同一行样式，只有“新建”两项保留用途说明 |
| 添加后多出草稿 | `applyDraft` 首次添加后把草稿改绑到新实例并继续保留；“编辑工作台”每次新建草稿 | 添加或应用成功后草稿关闭；再次编辑复用该实例未应用的草稿 |
| 已移除项只能恢复 | 草稿只能删除、实例只能移除；实例删除在规格 §6.2 中待定 | 已移除的自定义实例提供确认后的永久删除，先停止其运行中会话 |

Web Interface Guidelines 审查的附带问题一并修正：添加浮层含标题与多操作行，改用对话框角色；可添加行去掉多余的“添加”尾注；删除确认的进行中文案由“正在保存…”改为“正在删除…”；重命名输入补 `name` 与 `autocomplete="off"`；来自已删除工作台的会话不再提供会跳到首项的“在工作台中打开”；E2E 中残留的 `添加 Overview` 改为中文标题。

## 依据

用户 2026-11-12 在对话中选择推荐或指定方案：选品“直接添加为实例”；草稿“随之关闭”；删除“同时停止运行中的会话”（在删除实例记录与保存数据、执行关联及指向它的草稿记录的基础上，会话历史、项目文件、包文件保留）；选品在同一项目“允许多个”。决定记录见 [09 WB-Q3.2、WB-Q12.1](<../../docs/09. Workbench Discussion.md#21-已确定事项>)，详细行为见[工作台规格 §9.8](../../specs/workbench/spec.md#98-fr-wb-001006008-工作台列表管理)。

## 范围

- 做：草稿生命周期、App 模板直接添加与重名编号、已移除实例的永久删除、添加浮层信息结构与样式、相关文档同步。
- 不做：包与草稿文件的彻底清理、跨 Project 移动、管理中心、撤销提示；页面内部内容不变。

## 技术决定（AI，2026-11-12）

- 删除只对已移除的自定义实例开放，宿主再次校验；停止会话失败时不删除。停止范围为 `originViewId` 等于该实例且活动不为 `none` 的 Session，包括页面发起的 Agent 执行与从该工作台对话框发起的会话。
- 草稿复用以“目标实例 + 来源 + 基础修订”为键；实例已应用其他版本后旧草稿不再复用，避免用户卡在“已应用其他版本”。
- 首次添加的实例接替草稿的导航行（位置与名称覆盖）；编辑应用删除草稿的导航行，保留实例自己的名称。
- 选品重名编号写入导航名称覆盖，后续模板升级改写包标题时不会覆盖编号。
- Renderer 应用成功后先切到实例再刷新列表，并在当前视图有进行中的宿主操作时跳过“已移除项自动跳转”，避免闪到首项。
