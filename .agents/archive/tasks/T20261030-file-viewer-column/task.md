修复：

- View 列宽（`app/shell.css`、`features/project/Workspace.tsx`、`styles/tokens.css`）：原规则让 View 对话列以 440px 为基准并可伸展，内容列基准为 0，只能分到剩余空间的一半；文件树也以对话列宽为基准。现在对话列保持设定宽度、不再伸展；文件树使用该 Project 的侧栏宽度，与 Session 一致；内容列以默认侧栏宽度（`--sidebar-default-width`，400px）为基准并占用多余空间。窗口较窄时三列一起压缩，符合 UX 第 5 节；空间充足时分隔条只在对话与内容之间调整，调宽侧栏也不会让内容列变宽。
- 右侧区域下限（`app/shell.css`）：查看器打开时，右侧区域最窄为其工具栏宽度（不计文件树），替代原 200px，工具与关闭按钮始终可点。
- 查看器操作栏（`features/tools/files/files.css`）：操作按钮在列宽不足时换行。

独立复验：一名未参与实现的 Agent 按需求和场景独立操作三轮，未采用实现者的结论。第一轮确认原问题已修复，但报告查看器操作栏被裁切，以及 View 分隔条在空间不足时无效并带动文件树；第二轮确认两者在默认设置下已修复，另报侧栏调宽后对话列被压到最窄；第三轮确认该问题已修复，未发现缺陷。非阻塞观察：1024 宽时 View 对话列约 189px，输入框的模型选择箭头与发送按钮重叠 1px，两者都可点击；侧栏调宽后，窄窗口中文件树仍是最宽的一列，属于按比例压缩的结果；复验者在项目刚打开时看到工作台选择自行跳转两次，无法归因，之后未再出现，本次改动不涉及导航。

自动化：`alignment.spec.ts` 新增两种模式三档宽度的查看列回归，断言内容列不小于对话列的 0.85 倍、右侧工具栏不被裁切、Markdown 查看器的操作按钮不超出列、View 分隔条双向有效，且在 Session 调宽侧栏后 View 内容列不随之变宽。三处修复分别撤回时，该用例都会失败。基于 dev `d924d2c`：受影响类型检查与 `Workspace.tsx` 相关单测 10 项通过；选择器选中的 `alignment`、`app`、`files`、`composer`、`project`、`workbench` 六份 E2E 共 30 项通过、1 项失败，最后一次修复后重跑的 `alignment`、`app`、`files` 20 项通过。失败的是 `workbench.spec.ts` 的工作台列表管理用例：测试仍在找已改为中文的“添加 Overview”按钮（`ff7585a`），dev 上已有此问题，由[界面规范化任务](../T20261112-workbench-ui-polish/task.md)跟踪，与本改动无关。

未覆盖：真实 CLI 链路（布局改动不涉及 Provider，文件引用由模拟 Provider 验证）；原生窗口拖动缩放（改用 `setContentSize`）；“更多文件操作”弹出的原生菜单（只确认按钮可点）；打包应用；减少透明度时的 solid 外观。
