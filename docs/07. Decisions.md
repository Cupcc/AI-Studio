### DEC-01 SQLite 驱动采用 `node:sqlite`

草稿 · 2026-10-09 · [T20261009-app-skeleton](../tasks/archive/T20261009-app-skeleton/research.md) 第 3 节

- **决定**：主进程使用内置 `node:sqlite`。数据库位于应用 userData 目录，不写入 Project 目录；迁移只向前、幂等；其他模块只通过 `CoreServices` 访问数据库。文件名、迁移命名与用法见 [apps/desktop/README.md](../apps/desktop/README.md) 第 4 节。
- **理由**：`better-sqlite3` 需按 Electron ABI 重编译，且与 Vitest 使用的 Node ABI 冲突；内置驱动已在 Electron 主进程和打包冒烟中验证可用。
- **注意**：`node:sqlite` 在 Node 24 仍为实验性，升级 Electron 时需复跑数据库测试。

### DEC-02 进程边界与类型化 IPC

草稿 · 2026-10-09 · [T20261009-app-skeleton](../tasks/archive/T20261009-app-skeleton/research.md) 第 2、5 节；用法见 [apps/desktop/README.md](../apps/desktop/README.md) 第 3 节

- **决定**：窗口开启 `contextIsolation`、`sandbox`，Renderer 经 `app://studio/` 加载并受严格 CSP 限制；默认拒绝新窗口、外部导航、`<webview>` 和权限请求。例外：新窗口请求中的 http(s) 链接交给系统浏览器打开，其余协议忽略；权限只对 Renderer 来源放行剪贴板写入（`clipboard-sanitized-write`），供代码块复制（2026-10-10，依据 Agent 回复 Markdown 渲染的确认，见 [T20261010-prototype-v02-alignment](../tasks/archive/T20261010-prototype-v02-alignment/task.md)）。例外（2026-10-13，运行时工具）：Browser 预览 WebContentsView 不加载应用 Preload，也不使用应用守卫，自带导航 / 新窗口 / 权限 / 下载处理（见[工具规格 §5.1](../specs/tools/spec.md#51-运行时实现细化)）；应用守卫按窗口所有权只安装在应用 Renderer 的 webContents 上。例外（2026-10-13，用户回复「我选1」确认）：生产 CSP 仅为 `style-src-elem` 增加 `'unsafe-inline'`，原因是 xterm 6 在运行时注入 `<style>` 且不支持 nonce，否则打包应用的终端没有颜色、等宽字体、光标和选区；`script-src`、`style-src` 与 `img-src` / `font-src` / `connect-src` 保持不变，样式因此无法加载外部资源。已否决 WebGL 渲染器（未验证，GPU 上下文数量风险）与 `adoptedStyleSheets` / nonce 垫片（依赖 xterm 内部实现，构建期固定的 meta CSP 也无法逐次生成 nonce）。参考：VS Code 工作台 CSP 同为 `style-src 'self' 'unsafe-inline'`。回归由 E2E 断言 xterm 样式真实生效。追加例外（2026-10-14，用户回复「放宽安全限制，先实现功能为主」）：`style-src-attr` 同样增加 `'unsafe-inline'`，因为 xterm 用 `setAttribute('style')` 写 24 位色，并在启用 `minimumContrastRatio` 时逐单元格调整前景；否则真彩色被丢弃、ANSI 彩色背景上的文字不可读（W5-F6、W5-F9）。同样没有任何路径把 HTML 注入主窗口，脚本与外部资源限制不变。每个功能声明一份 IPC 契约，Preload 按契约通用生成 `window.studio`，主进程处理器先校验输入再执行；契约与处理器各在登记文件中加一行。
- **理由**：满足 04 第 3 节“Preload 只暴露最小化、类型化 IPC”，并让并行 task 只在登记文件中各加一行。
- **放弃**：通用 `invoke(channel)`（任意通道可调用）、手写 Preload 桥接（易与契约不一致）、tRPC 类框架（当前不需要）。

### DEC-05 Project View 渲染

已确认（2026-10-09） · 04 第 1 节第 3 项 · Q3、Q4、Q5

- **决定**：V1 只实现声明式渲染：View Definition 是经 Schema 校验的 JSON，Agent 只能选择受信组件、布局和数据绑定，不能提供 HTML、脚本或任意 CSS。校验或渲染失败时保留上一次成功版本并显示错误。自由 HTML（无同源权限、禁网的沙箱 iframe）作为后续第二层，启用前需原型验证。
- **理由**：强制事实与展示分离（FR-VIEW-004），Agent 输出不会获得任何执行能力，关系图版式也更稳定。
- **取舍**：Agent 只能在组件词汇范围内设计 View。01、04 中“AI Generated UI / HTML”在 V1 按此理解，自由 HTML 推迟到 P1 / 自定义 View（Q3，2026-10-09 确认）。
