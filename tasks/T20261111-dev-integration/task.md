# 建立 dev 集成分支

## 授权与范围

用户于 2026-11-11 确认使用长期 `dev` 分支集成功能，要求新建分支、提交当前成果、处理集成冲突，并让主目录停在 `dev`，之后由用户测试。后续明确本轮只处理 commit、merge 和冲突，不执行 AI 界面审查或额外功能验收；保留现有提交门禁。

`main` 保留当前稳定基线 `6e891415117a1efb6469620702b0c67870e18709`，本轮不向 main 合入。功能分支和原 worktree 保留，待验证与稳定交付后再清理。分支流程由 [CONTRIBUTING.md](../../CONTRIBUTING.md#2-分支规范) 统一维护。

## 集成步骤

1. 备份主目录、网页格式与工作台管理目录的未提交文件、差异和内容摘要。
2. 从 main 新建 dev，保存主目录中已有的统一宿主、标准网页包与协作文档成果。
3. 以统一宿主工作目录为共同文件基线，把工作台管理变化移植到新的标准包宿主，保留网页格式任务的新实现。
4. 更新分支规范及 dev 的 CI 触发，完成提交门禁和最终 diff 复核。
5. 主目录留在 dev，提供提交与测试入口。人工产品验收状态为待人工验收。
