## 1. 验收使用原则

- 本文件的 AC 是 **V1 核心端到端验收场景**，不是对全部 FR 的逐条测试用例全集。
- 每个实现任务应引用对应 FR；测试用例可在核心 AC 基础上继续细化边界、异常和平台兼容场景。
- 如 AC 与 FR 描述不一致，应先修正规格，不应由测试阶段自行改变产品语义。
- 验证分工、任务收尾与人工功能 / 阶段验收按 [Task Protocol](../tasks/README.md#acceptance) 执行；本文件只定义产品预期，task 完成不代表对应 AC 已通过或产品已获人工验收（2026-10-11 确认，治理规则 diff 待审阅）。
- V1 首发验收平台为 macOS；最低系统版本及 CPU 架构覆盖仍待打包确认。2026-10-08 的 [CLI 开发前校验](../tasks/T20261008-cli-preflight/report.md)提供 Adapter 实现输入，不替代本文件的端到端验收。


## 2. V1 核心验收场景

### AC-01 多项目

用户同时打开三个本地项目。

能够通过顶部 Project Tabs 快速切换。

三个 Project 的：

- Session；
- Project View；
- Context Panel 状态；

保持独立。

---

### AC-02 创建 Codex Session

用户在 Project A 创建 Codex New Chat。

输入需求后：

- Codex 正常开始执行；
- Session 出现在左侧；
- 显示 Running；
- Conversation 流式输出。

---

### AC-03 并发执行

用户在同一 Project 创建：

- 一个 Codex Session；
- 一个 Claude Code Session。

两个 Session 可以同时执行。

切换 Session 不应打断后台执行。

---

### AC-04 完成提醒

用户正在 Session B。

Session A 在后台完成。

结果：

- Session A 出现绿色圆点；
- 用户点击 Session A；
- 页面直接显示最新 Conversation；
- 绿色圆点消失。

---

### AC-05 Needs Input

后台 Agent 需要用户做决定。

Session History 中必须出现明显 Needs Input 状态。

用户点击后可以直接看到 Agent 当前等待内容。

---

### AC-06 Project View

用户打开 Architecture。

页面显示：

- 左侧 Conversation；
- 右侧 Architecture Preview。

用户输入：

“重新整理支付模块架构。”

系统可以通过普通 CLI Session 处理请求，并更新 Architecture Preview。

---

### AC-07 工具面板

用户可以分别打开：

- Files；
- Diff；
- Browser；
- Terminal。

关闭后 Main Canvas 恢复空间。

Agent 不得自行强制打开这些 Panel。

依据 FR-TOOL-002、FR-TOOL-004 的 2026-10-10 确认，补充工具内容验收：

- Project Diff 覆盖相对 HEAD 的已暂存、未暂存和未跟踪文件，支持 M / A / D、文件列表和单文件 Diff；不提供 MVP 范围外的 Git 操作界面。
- 从完成行打开本轮原生 Diff，明确显示范围；保存后的补丁不随后续工作区修改而改变。覆盖多 Session 并行，不能混入其他轮次记录。
- 原生数据不可用时按 FR-TOOL-002 显示降级入口；非 Git 项目显示说明与指引，不自动初始化或创建快照。CLI 能力与覆盖边界须记录验证结果（04 第 1 节第 13 项）。
- 同一 Project 可同时运行至少两个独立 Terminal 实例（如开发服务器与测试命令），支持新建、切换、关闭；切换 Session / Project、隐藏面板和 Session Stop 均不终止用户终端。关闭一个实例不影响其他终端或 Agent Runtime。

依据 2026-10-12 确认的 DEC-10 及 FR-TOOL-001～004，补充以下验证：

- Files 展开目录和查看文件按需读取；增删 / 更新后的树与文件内容正确，有效的展开和选择保持，查看不自动附加上下文。
- 历史轮次只有 patch 时仍按保存内容显示；不能用当前文件伪造历史两侧内容。未跟踪文件、特殊文件名、无 HEAD、二进制及大文件按工具规格验证对应内容或明确降级。
- Browser 实际打开 localhost；网页无法访问应用 Node / IPC。工具切换、Project 切换及窗口 resize 后没有页面遮挡当前内容，加载失败能反馈，关闭所属 Project 后释放实例。
- Terminal 面板被隐藏 / 卸载后重新显示时，进程和屏幕 / 输出状态可继续使用。关闭确认、取消和最后一个 Tab 的空状态按 [工具规格](../specs/tools/spec.md#fr-tool-004-terminal) 验证；清理隔离遵循 04 第 5 节。

本轮范围澄清不新增 AC 编号（2026-10-11 确认；DEC-11）：AC-03 的并行验证不包含文件冲突检测或自动 Worktree 隔离；AC-06 按 FR-VIEW-003 由用户通过普通 Session 发起生成；AC-07 按 FR-TOOL-002 区分项目变更与原生轮次记录，不以全量 Agent 归因为验收目标。

## 4. 当前验收覆盖边界

退出与异常清理专项按 [04 第 5 节的责任边界](<04. Technical Requirements.md#退出与异常清理责任边界>) 验证正常退出清理、失败诊断、异常后归属检查及误清理防护；不得将“任何异常退出即时零残留”或清理共享 / 归属不明的外部进程列为验收要求。受管进程清理和既有 Stop 退出证据仍须验证，不以范围澄清将未通过项改为通过（2026-10-11 确认；DEC-11）。

现有 AC 聚焦产品最核心的端到端闭环。以下内容仍应在测试设计阶段依据 FR/NFR 补充专项测试：Session Resume、Rename、Model Selector、错误恢复、大量 Session 性能、多 Project 后台运行、Project Knowledge / View 数据分离、Browser/Terminal 边界、CLI Adapter 状态映射、本地持久化，以及原型阶段补充的 New Chat 草稿、Needs Input / Error 清除规则、Project Tab 注意力点和关闭 Project 确认（见 UX Specification 第 10 节）等。该列表用于测试规划，不改变其 P0/P1 定义。

Stop 专项测试应依据 FR-INPUT-001、FR-SESSION-003、FR-PROJ-002 和 Technical Requirements 第 5 节覆盖：本轮命令归属与退出、先前后台服务的清理范围、其他 Session / 用户 Terminal 隔离、重复 Stop / 迟到事件、实验接口不可用或清理失败后的 Runtime 兜底，以及原 Session ID / 上下文恢复。2026-10-08 的原生 Stop 复核已提供接口层证据，见 [CLI Integration Preflight](../tasks/T20261008-cli-preflight/report.md) 第 4、5 节；上述产品与异常场景仍待端到端验收，不能将接口检查通过视为 AC-03 或全部 Stop 行为已验收。

依据 [01 第 8 节原则 24](<01. Product Definition.md#8-已确认的产品原则>) 与 FR-INPUT-001，增加原生能力对齐专项：分别从应用界面验证 Codex 运行中追加、Claude 原生排队及各自消息接收、回合归属、Stop 后队列和续聊行为；检查原生可见输出、配置、模型及其他对话控制是否被客户端额外裁剪。按 CLI / SDK / 应用代码版本记录已接入、待实现、接口未开放及已知不兼容的证据。未实现不得以“产品不支持”豁免；版本探测、登录成功和模拟测试均不能替代真实兼容性结果。此专项承接 AC-02／AC-03／AC-05，补充输入控制的覆盖，不更改原 AC 编号（2026-10-11，diff 待审阅）。
