## 1. 已确认方向

用户通过对话或模板创建适合自己工作的 Web 页面，AI 使用现有 CLI Session 生成内容，宿主将产物绑定到页面指定位置。先以五图场景设计原型，再评审具体交互。已确定的结论见 §2.1，原型暂采纳方案与后续问题见 §2.2，技术验证见 §2.3。

## 2. 讨论问题确认记录

### 2.1 已确定事项

本表记录用户接受的推荐结论。原问题含有后续待定部分时，拆到 §2.2，不把整个问题标成全部解决。

| 编号 | 问题 | 已确定结论 | 确认日期 |
|---|---|---|---|
| WB-Q1 | 是否支持开发之外的创作任务 | 支持，以本地 Project 和现有 CLI Session 为基础；先用五图场景开展原型设计 | 2026-11-10 |
| WB-Q2 | 是否支持自定义 Web 页面 | 支持，页面配结构化定义；声明式组件保留为模板 | 2026-11-10 |
| WB-Q3 | 创建和修改工作台采用哪些方式 | 对话生成、内置模板起步、编辑预览和添加至 Project；本地包导入与分享后续处理，不先做通用拖拽编辑器 | 2026-11-10 |
| WB-Q4 | 内容生成能否顺带修改工作台结构 | 默认只更新内容，结构修改走明确的编辑入口 | 2026-11-10 |
| WB-Q5 | 成功产物是否直接展示 | 校验后逐项展示并保留旧版；不要求每张图另点确认才能预览，作品质量由用户判断 | 2026-11-10 |
| WB-Q7 | 包分享与带成果分享是否分开 | 分开；包默认不带成果，带成果分享通过实例导出，不携带对话或凭据 | 2026-11-10 |
| WB-Q8 | 原型阶段是否迁移默认五个 View | 保留现状；是否迁移、隐藏和重排，留到原型评估后决定 | 2026-11-10 |
| WB-Q9 | 状态保存采用什么方向 | 宿主管理实例绑定，产物保存在 Project 内；首期说明项目文件与宿主状态的备份依赖，实例导出留到分享阶段 | 2026-11-10 |
| WB-Q10 | 是否采用包与实例分离的小型宿主 | 采用，复用导航和 Session；参考 Harness 的组织方式，不整体复制框架或承诺包兼容 | 2026-11-10 |
| WB-Q11 | 安装、固定、停用和移除是否分开 | 分开处理，能力声明不自动授予权限；具体入口与呈现待设计 | 2026-11-10 |
| WB-Q12 | 停用和删除的基本边界是什么 | 停用页面不等于停止生成，已授权执行仍可提交；删除撤销写回并保留可恢复成果。是否同时 Stop、保留期限与彻底清理仍待确定 | 2026-11-10 |

### 2.2 未确定事项

保留原问题编号，拆出的细节使用 `.1` 等后缀。以下区分原型设计采用的方案和后续范围；“暂采纳”是设计依据，不是最终设计确认。

#### 暂按推荐方案设计，待原型评审

用户于 2026-11-10 接受先采纳推荐方案制作原型、看到效果后再调整。下表各项均按推荐答案设计，不需逐项确认后才开工；评审时可以保留、修改或替换方案。删除等操作先呈现交互和示例状态，不在设计原型中执行真实数据操作。

| 编号 | 问题 | 暂采纳方案 | 原因与主要取舍 | 评审定稿时点 |
|---|---|---|---|---|
| WB-Q3.1 | 创建、编辑、预览和添加至项目的入口如何组织 | 宿主提供“添加工作台”，进入后选对话创建或模板；草稿预览后再添加。“编辑工作台”放在实例操作中，预览后应用 | 能分清设计草稿与正在使用的实例，减少误改成果；创建与编辑需要分别呈现状态 | 原型设计完成后评审，相关界面实现前确定 |
| WB-Q4.1 | 生成与结构编辑如何切换和提示 | 日常对话留在内容模式；明确进入编辑时展示草稿状态，应用前说明位置增删对现有内容的影响 | 避免出图时误改定义；增加一次明确的模式切换 | 原型评审时 |
| WB-Q5.1 | 如何选择目标、展示进度、替换结果和恢复旧图 | 页面可选中内容，输入区显示目标名称；生成中保留旧图，成功后替换；失败可局部重试，历史版本提供恢复入口 | 用户能看清改哪一张、保留了什么；需设计选择、处理中、部分失败和历史状态 | 原型评审时 |
| WB-Q9.1 | 保存恢复和备份体验如何呈现 | 内容自动保存，显示真实保存状态与失败反馈；明确完整备份需包含项目文件和宿主状态 | 用户无需反复手动保存，也能知道恢复边界；备份不是只复制一个目录 | 保存反馈在原型评审时确定；备份与恢复规则在存储实现前确定 |
| WB-Q11 | 安装、固定、停用、移除及权限说明如何呈现 | 安装前展示来源和所需能力；添加实例后进入项目导航，固定与停用使用不同操作 | 避免把隐藏入口当成停用或删除，也避免能力声明被误认成授权；增加操作说明和状态设计 | 首个原型评审时；完整多实例管理见下表 |
| WB-Q12.1 | 删除实例时是否同时停止运行中的生成 | 删除时一并 Stop，并在确认中列出受影响 Session；保留对话历史和可恢复成果 | 避免继续生成无法写回的结果及后续费用；会中断这些 Session 当前回合，需要明确提示 | 生命周期原型评审时、删除功能实现前 |

#### 后续范围，暂不展开

下表保留推荐答案与原因，不纳入首个原型，也不阻塞当前设计。进入对应阶段时再设计和评审。

| 编号 | 问题 | 推荐答案 | 原因与主要取舍 | 决策时点 |
|---|---|---|---|---|
| WB-Q7.1 | 本地包导入和实例导出如何操作 | 分成“导出工作台包”和“导出含成果的实例”；导入先校验声明、版本和资源，再创建新实例 | 导出范围清楚，减少误带项目数据；需要额外的状态快照和资源恢复逻辑 | 分享功能设计评审时、实现前 |
| WB-Q8 | 默认五个 View 是否迁移、能否隐藏或重排 | 原型评估后再决定是否分批迁移；先验证工作台能否完整承载现有 View，再讨论隐藏与排序 | 可依据实际体验和迁移成本判断；暂时并存两套呈现方式 | 原型评估后、默认 View 改造前 |
| WB-Q12.2 | 可恢复成果保留多久，何时彻底删除 | 首期建议不自动过期，提供显式永久删除并说明影响；清理前检查产物是否仍被引用 | 避免时间到期后意外丢失成果；代价是占用磁盘，需要后续清理入口 | 数据清理方案评审时、删除与清理实现前 |
| WB-Q11.1 | 完整多实例管理如何组织 | 后续提供项目内管理入口，集中查看实例、固定与停用状态；同包实例独立命名和管理 | 实例较多时便于查找和维护；首个原型先验证单实例主流程，避免提前建设管理中心 | 多实例管理阶段设计评审时、实现前 |

### 2.3 待验证的技术方案

以下技术项不阻塞交互原型设计。设计原型使用明确标注的示例状态，具体工具和实现方案由实施 Agent 验证后确定；结果若影响用户体验，回到原型调整，涉及费用或数据权限的取舍交产品负责人决定。

用户于 2026-11-10 指定 Codex CLI 与 image2.5 作为验证路径，连接信息使用本地 `.env.local` 中的 `LLM_gateway` 和 `api_key`；随后明确本产品是内部企业工具，先完善功能，不先开展页面安全专项设计。页面容器先服务加载、展示、宿主通信和状态更新，安全专项后置，不作为首期功能接入或验收门槛。上述为对话决定，具体实现与本文 diff 仍待审阅。

| 编号 | 问题 | 推荐方案 | 原因与主要取舍 | 确定时点 |
|---|---|---|---|---|
| WB-Q6 | 首期采用哪个 CLI 和出图工具 | 使用用户指定的 Codex CLI 与 image2.5，验证网关模型 ID、参考图、文件返回、费用、Stop 和错误反馈；设计原型先用标明的示例状态 | 验证路径已有输入，可直接开展接通验证；工具选择不代表真实能力已验证 | 路径已指定；真实出图前完成接通验证 |
| 技术项 | 自定义页面使用什么容器 | 按内部企业工具功能优先推进；iframe 作为嵌入候选，先验证页面加载、布局、宿主通信、状态更新和卸载，按功能需要选择最终容器 | 先走通五图工作流；安全专项设计后置，不以隔离验证阻塞首期功能 | 功能原型中确定容器；安全专项在功能完善后另行安排 |
| 技术项 | CLI 如何读取工作台并提交产物 | 先试限定本次执行范围的本地命令桥，不可行时评估 MCP | 可复用 CLI 的 Shell 工具；需验证发现、连接、错误返回和退出清理 | CLI 接入技术验证后、真实出图前 |
| 技术项 | 包格式、SDK、版本与存储目录如何定稿 | 以五图主流程所需的最小字段和接口起步，验证编辑、冲突与恢复后定稿；不改变现有 Git 忽略策略 | 减少提前设计通用平台的成本；需保留版本标识以支持后续升级 | 对应技术验证后、持久化与接口实现前 |
