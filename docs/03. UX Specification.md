## 3. 总体页面结构

客户端采用四个主要区域：

1. 顶部 Project Tab Bar；
2. 左侧 Project Navigation / Session History；
3. 中央 Main Canvas；
4. 右侧可折叠 Context Panel。

基本结构：

```text
┌───────────────────────────────────────────────────────────────┐
│ Project A × │ Project B × │ Project C × │ +                  │
├──────────────┬─────────────────────────────────┬──────────────┤
│              │                                 │              │
│ Project View │                                 │ Files        │
│ Navigation   │                                 │ Diff         │
│              │          Main Canvas            │ Browser      │
│──────────────│                                 │ Terminal     │
│              │                                 │              │
│ Sessions     │                                 │              │
│              │                                 │              │
│ ⚙ 设置       │                                 │              │
└──────────────┴─────────────────────────────────┴──────────────┘
```

右侧 Context Panel 默认允许收起。

顶栏（Project Tab Bar）左侧放置左侧导航折叠按钮，右端放置右侧边栏（Context Panel）按钮。

左侧导航左下角固定“设置”入口；设置以应用内对话框打开，也可通过菜单栏“设置…”或 ⌘, 打开（FR-SET-001）。

## 4. Project View 交互模型

Project View Mode 的权威功能要求位于 **FR-VIEW-005 ~ FR-VIEW-008**。设计实现必须满足以下已确认约束：

- Main Canvas 使用 **左 Conversation、右 Project View Preview** 的左右结构；
- Conversation 保持完整纵向空间，Preview 保留足够二维展示空间；
- Project View 左侧对话仍是普通 CLI Session，不创建特殊 Project Chat；
- 从 Project View 创建 New Chat 时，新 Session 同步进入 Session History；
- 一个 Project View 不永久绑定唯一 Session；
- 用户可以在描述修改需求的同时观察 Preview 更新。

```text
┌──────────────────────┬──────────────────────────┐
│                      │                          │
│    Conversation      │      View Preview        │
│                      │                          │
│                      │                          │
│                      │                          │
│ ┌──────────────────┐ │                          │
│ │ Input            │ │                          │
│ │ Model          ↑ │ │                          │
│ └──────────────────┘ │                          │
└──────────────────────┴──────────────────────────┘
```

## 5. Context Panel 交互模型

- Context Panel 支持展开/收起；
- Files / Search / Diff / Browser / Terminal 由用户主动打开和切换；
- AI 不因执行任务自动弹出、切换或改变这些工具；
- Workspace 布局保持稳定、可预测；
- 工具面板不得抢占 Main Canvas 的主视觉层级；
- 入口为顶栏右端的单一右侧边栏按钮；展开后默认显示该 Project 上次选择的工具（P-C）；
- 面板顶部以图标切换 Files / Search / Diff / Browser / Terminal，悬停显示名称；同一时间只显示一个工具；
- 点击右侧边栏按钮或面板关闭按钮即收起；
- 宽度可拖拽调整，并按 Project 记忆；
- Project View Mode 下，工具与 Preview 共享右侧区域：区域顶部以图标在 Preview 与工程工具之间切换，打开工具即替换 Preview；点击 Preview 图标或右侧边栏按钮回到 Preview（P-B）。工具打开时，右侧区域顶栏保留“关闭右侧工具”×；点击后回到 Preview，右侧区域仍保留（2026-10-11 确认）。Files 查看文件时的额外列见下文。

Files 文件查看布局（用户 2026-10-30 请求）：点击文件后，在文件树左侧、Conversation 右侧显示文件内容，导航展开时形成四列；关闭查看器或切换其他工具时收起内容列。两种画布模式均适用；窗口较窄时三列内容区域共同压缩。

Diff 与 Terminal 的内容交互补充（2026-10-10 确认；FR-TOOL-002、FR-TOOL-004）：

- 从工具入口打开 Diff 时查看“项目变更”；从 Conversation 轮次完成行进入时查看该轮的“本轮变更”，标题标明范围及关联轮次，不静默切换数据来源。
- 本轮记录不可用时，显示“本轮变更不可用”及“查看项目变更”入口；非 Git 的项目变更显示说明和 Git 初始化指引。数据边界见 FR-TOOL-002。
- Terminal 内部用 Tab 切换实例，提供新建和关闭入口；同一时间只显示一个工具；Terminal 可在该工具内分屏多个实例（DEC-25，2026-10-26 确认）。收起工具面板与关闭 Terminal Tab 是不同操作，收起面板保留进程和输出。
- 组件结构见 [Shell Spec v02](../design/components/shell-spec-v02.md) 第 6、9 节。

2026-10-12 确认的内容与状态原则（DEC-10）：Files 按需加载，刷新保留有效的展开 / 选择；查看与加入上下文分开。隐藏或切换工具时资源由所属服务保留，重新显示终端能继续看到输出。本轮 Diff 原文不足时展示已保存补丁，不能显示由当前文件推导的历史内容。具体加载、异常、生命周期与接口见 [工具规格](../specs/tools/spec.md)，本次未改变面板布局。

2026-10-26 确认补充（DEC-25）：工具交互参照 VS Code：Files、Terminal 使用 macOS 原生右键菜单；⌘P 快速打开以顶部居中的面板出现，选择后打开 Files；工具快捷键沿用 VS Code（⌘⇧E Files、⌘⇧F Search、⌃⇧G Diff、⌃` Terminal、⌥⌘/ Browser）。快捷键与菜单仍属用户主动操作，Agent 不触发。Search 作为第五个工具图标位于 Files 之后。Browser 的导航范围与登录数据改按 FR-TOOL-003 的 2026-10-26 段落，下段相关内容由其取代。

2026-10-13 确认补充（DEC-14）：Browser 的本地导航、外站提示及登录恢复边界遵循 FR-TOOL-003；用户拒绝外站打开时保留当前页面。Files 标签必须对应真实提交的文件引用；提交失败保留输入与标签并说明原因，不把仅保存标签呈现成 CLI 已接收。Project 关闭 / 退出应用的确认同时列出受影响的 Session 与未退出 Terminal，取消不改变资源，清理失败显示诊断及重试入口，详见 FR-PROJ-002 与 Project spec §3.2.4。

## 6. 页面行为

### 启动页与新增 Project

- 没有打开任何 Project 时显示启动页：“打开本地目录”与最近打开的 Projects；
- Project Tab Bar 的 `+` 在新 Tab 中打开同一启动页；
- 选择的目录已经打开时，切换到对应 Tab（FR-PROJ-001）。

---

### New Chat

1. New Chat 位于左侧导航顶部，主按钮使用应用级 Default CLI；
2. 右侧下拉菜单按固定顺序列出已启用的 CLI，并提供“设为所有 Project 默认”和“CLI 设置”；Project View 的新建选择器同样隐藏未启用项；
3. 默认 CLI 是应用级偏好，选择一次后所有 Project 的新对话均使用它；未设置或该项不可用时为第一个已添加且可用的 CLI；已添加 / 未添加分组、固定右上检测与草稿回退由 [settings spec](../specs/settings/spec.md#cli-管理与默认-cli2026-10-25-确认)负责（2026-10-25 确认）；
4. 已添加但未安装或未登录的 CLI 在菜单中禁用，并说明原因；Composer 提供“使用 <可用 CLI>”和“CLI 设置”入口；
5. 点击后进入新对话草稿，发送第一条消息时创建 Session（FR-CHAT-001）。
6. 新对话输入框与已有 Session、Project View 共用底部位置，问候语和轻量起步示例留在正文区域。示例只填入空白草稿并聚焦，不自动发送或覆盖非空正文；详见 [chat spec §3](../specs/chat/spec.md#3-行为细则)与 [Shell Spec v02 §6～7](../design/components/shell-spec-v02.md#6-conversation)（DEC-23，2026-10-23 确认）。

---

### Session 打开

用户点击一个 Session：

1. 清除其 Completed Unread 或 Error 提醒；
2. Main Canvas 切换为 Conversation Mode；
3. Conversation 直接显示最底部；
4. 输入区可立即继续输入。

如该 Session 创建于某个 Project View，Conversation 顶栏显示来源 View，并提供“在工作台中打开”入口。

---

### Project View 打开

用户点击一个 Project View：

1. Main Canvas 切换为 Project View Mode；
2. 左侧 Conversation；
3. 右侧 Preview；
4. 用户可以继续使用已有 Session 或创建 New Chat；
5. 当前 View 作为 Session Context 的一部分。

从左侧导航进入 View 时，左侧 Conversation 为新对话草稿，不创建 Session；草稿的底部输入框上方列出该 View 最近的对话，无记录时不显示区块，点击即可继续（P-A；DEC-23，2026-10-23 确认）。继续某个对话后，Conversation 顶栏显示 Session 标题，并提供新建对话按钮。

切换 Project Tab 后返回时，按 FR-PROJ-003 恢复离开时的完整状态，包括正在显示的对话；新草稿规则只用于从导航进入 View。

---

### 用户自定义工作台

预设和自定义页面共享网页插件容器与操作反馈。页面内容及 Overview Session 分组在同一 iframe 内显示，宿主保留导航、Conversation、工具切换，以及右侧区域标题栏中的状态标记与“更多操作”菜单；宿主不提供页面缩放，带画布的页面自行提供（DEC-30）。页面行为与公共能力见[工作台规格 §9.7](../specs/workbench/spec.md#97-预设与自定义工作台统一宿主)。

列表管理按用户 2026-11-11 确认补齐，入口、排序、移除恢复与删除影响由[工作台规格 §9.8](../specs/workbench/spec.md#98-fr-wb-001006008-工作台列表管理)负责。

来源：FR-WB-001～008 候选需求、DEC-28。按 2026-11-11 的[架构先行决定](<09. Workbench Discussion.md#1-已确认方向>)，当前建设最小插件机制；创建、预览、添加和修改交互随真实机制评审。以下保留 [09 §2.2](<09. Workbench Discussion.md#22-未确定事项>)候选方案，具体呈现可调整。方案中宿主提供“添加工作台”，支持 AI 对话创建和内置模板。预览先展示草稿；“添加至当前项目”创建实例并加入导航，不触发出图。来源与能力说明放在“更多操作 → 关于此工作台”，能力声明不等于授权。

从导航打开实例后，复用左侧普通 Conversation 与右侧工作台页面。以下内容交互属于后续业务阶段：页面允许选择内容、预览产物和填写可编辑的指令草稿，发起模型调用仍由用户发送。每次发送前能查看并移除工作台上下文；“第三张”等位置表达以发送时顺序解析，目标不唯一时先澄清。

“编辑工作台”与日常生成分开。更新某张图片期间继续显示旧图；新结果校验后直接展示，旧版可恢复。部分失败显示真实结果与失败原因，不虚构进度。页面切换、停用、Stop 和删除按[工作台生命周期](../specs/workbench/spec.md#62-导航与生命周期)呈现为不同动作。

插件机制与后续业务的阶段范围见[路线图 §4.2](<06. Development Roadmap.md#42-插件架构与工作台建设>)。预设与自定义工作台统一在“工作台”导航区域，来源分类见 [01 Workbench](<01. Product Definition.md#workbench>)；预设的内容、生成及只读 Preview 行为继续保留（2026-11-11，DEC-29）。

### Project 切换

用户点击顶部其他 Project：

- 切换整个 Workspace Context；
- 恢复该 Project 上一次状态；
- 不停止其他 Project 中已经运行的 Session。

### Project 关闭

关闭 Tab 时按 FR-PROJ-002 同时检查 Running / Needs Input Session 与未退出 Terminal，任一存在则合并确认；两者均无才不提示并进入资源释放。退出应用同样汇总确认，清理失败保留诊断与重试；具体流程见 [Project §3.2.4](../specs/project/spec.md#324-关闭-tab-与确认)（2026-10-13 确认，DEC-14）。

### Agent To-dos（后续阶段）

2026-10-31 范围确认见 DEC-26；以下是待审阅交互方向，不是已实现布局。Agent To-dos 不替代普通 Session；应用级入口提供总收件箱和全部任务，Project 内提供快捷视图。

总收件箱聚焦需要用户处理的事项，范围及普通 Session 去重由 [FR-TODO-003](<02. Functional Requirements.md#fr-todo-003-跨-project-总收件箱>)负责。全部任务提供看板 / 列表、Project / 状态筛选和搜索；详情使用可返回原列表上下文的面板，承载结果、时间线、会话和 Diff。延后 / 归档不标记 Done；合入中的任务仍可追踪，但不作为待用户答复数量。

按[路线图 §4.1](<06. Development Roadmap.md#41-agent-to-dos-分阶段建设规划>)逐步开放操作；未交付的执行 / 合入动作不能显示为可用。总收件箱、任务详情、普通 Conversation 往返时保留筛选、滚动与工作区布局，不由任务事件自动抢焦点。视觉稿和完整键盘流程在对应阶段补充。

---

### Needs Input 与 Error 呈现

- Needs Input：在 Conversation 末尾显示等待卡片，内容为 CLI 原生的问题和选项（如允许 / 拒绝、选项列表），按钮直接回传给 CLI；输入框保持可用，用户也可以直接输入回复。打开 Session 时位于最底部，可立即看到等待内容（AC-05）。
- Error：在 Conversation 末尾显示错误卡片，包含错误摘要和“重试”，错误详情可展开查看。

### Running 期间输入与原生能力

按 FR-INPUT-001 与 [01 第 8 节原则 24](<01. Product Definition.md#8-已确认的产品原则>)，Running 期间保留原生支持的发送入口及 Stop 入口，不能因复用同一个按钮而禁发。输入反馈区分“追加到当前回合”和“排队待执行”；收到接收确认后才显示已接受，不能把排队显示成已经执行。具体控件组合由实现确定，须同时可访问且不改变原生语义。原生向用户公开的输出与控制不能仅因早期原型未绘制而省略；接口接入缺口按负责 spec 跟踪（2026-10-11 确认原则的交互落实；diff 待审阅）。

---

### Project View 空状态与更新

- Project Knowledge 尚未生成时，Preview 显示空状态和“生成 <View 名称>”入口；点击后把可编辑的生成指令填入左侧输入框，由用户发送（FR-VIEW-003）；
- Overview 中的 Recent Sessions、Needs Input、Recently Completed 来自客户端 Session 数据，Knowledge 为空时也直接显示；
- 五个默认 View 的 Preview 只读，支持滚动，修改通过 Conversation 完成；自定义工作台按本节的[工作台交互](#用户自定义工作台)处理；
- Agent 更新 Knowledge 或 View 后 Preview 自动刷新，并显示“已更新”时间；刷新不改变 Workspace 布局；
- 渲染失败时保留上一次成功渲染的版本，并显示错误提示。

## 7. 状态视觉规则

V1 状态色应尽量克制。

建议：

| 状态 | 建议表现 | 清除时机 |
|---|---|---|
| Running | 中性色 Spinner / 动态点 | 当前一轮结束 |
| Needs Input | 黄色/橙色小状态点 | 用户作出答复（FR-STATE-002） |
| Completed Unread | 绿色圆点 | 用户点击查看该 Session（FR-STATE-005） |
| Error | 红色状态点 | 用户点击查看该 Session（FR-STATE-003） |
| Normal History | 无任何状态 | — |

原则：

- 不大面积使用状态色；
- 状态主要用于 Attention；
- 无事件时不增加视觉元素。

### Project Tab 注意力点

- 非当前 Project 的 Tab 显示该 Project 中优先级最高的一个注意力状态：Needs Input > Error > Completed Unread；
- 只显示一个点，不显示数量，不显示 Running；
- 当前 Project 的 Tab 不显示，相关状态已在左侧 Session History 中可见；
- 当前 V1 仍只显示单个 Project Tab 注意力点；后续总收件箱的统一聚合与去重由 FR-TODO-003 负责，不因此回写当前 Session 提醒已实现。

## 8. UI 设计要求

### 整体视觉

要求：

- 以中性色为主：使用毛玻璃外观，系统开启“降低透明度”时改用纯色外观，毛玻璃可选背景颜色；颜色模式默认跟随系统，可选浅色或深色（FR-SET-002；2026-10-12 对话确认，本次 diff 待审阅）；
- 中性色体系；
- 少量状态色；
- 大面积留白；
- 边界弱化；
- 不使用密集 Toolbar；
- 不设计大型 Dashboard Chrome；
- 不采用传统 IDE 的深色高密度布局。

---

### 文字与信息层级

界面应尽量让控件、状态和反馈承担说明，采用“自解释界面 + 按需披露”，而不是把交互规则写成常驻段落。每个文字元素只承担一个任务：标签说明对象，操作说明动作，状态说明当前结果，反馈说明刚刚发生的变化。

要求：

- 主路径只保留完成当前任务所需的标签、操作、状态和结果；用户能从布局、控件状态或即时反馈推断的信息，不再用常驻说明重复表达。
- 选择、默认、可用性和范围优先用可观察的界面状态表达：选中态、勾选、状态标记、分组和短暂 Toast；不要把“点击后会怎样”写成固定说明。
- 帮助采用渐进式披露：优先使用 Tooltip、Popover、Info 或帮助链接；提示只补充当前控件所需的信息，不重复可见标签，也不承载长篇教程。
- 只有图标、或窄宽度下折叠为图标或编号的控件，悬停与键盘聚焦时显示名称提示，样式与主界面提示一致，并保留无障碍名称。
- 必须保留不可从界面推断的影响范围、权限、数据风险、不可逆后果、错误恢复方式、陌生概念解释和空状态下一步。
- 不为“立即生效”“所有 Project 共用”等可由状态或设置层级直接看出的事实增加说明性句子；确需确认时，用短暂、具体的结果反馈，例如“已添加 Codex CLI”。
- 设计评审时逐句删除文案并复核：删除后用户是否仍能完成任务、理解重要影响并恢复错误？若答案为“是”，删除该文案；若答案为“否”，将其放到最接近问题的上下文中。
- 视觉简化不等于隐藏语义：键盘焦点、无障碍名称、状态和错误信息仍须通过可访问的控件语义与辅助技术可获得。

CLI 设置示例：

| 不保留的常驻文案 | 由什么表达 |
|---|---|
| “点选后立即生效。” | 选中态与即时视觉变化 |
| “点击可用的 CLI 设为默认，所有项目共用。” | 可点击行、默认勾选和“应用默认”分组语义 |
| “已添加全部支持的 CLI。已应用到所有 Project。” | “已添加”列表；必要时仅用短暂结果 Toast |

---

### 左侧导航

要求：

- 宽度稳定；
- 工作台与 Sessions 有明显层级；
- Session History 可持续增长；
- Selected 状态明确；
- Hover 状态克制；
- Session 状态点不影响标题阅读；
- New Chat 位于导航顶部，其下依次为工作台与 Session History；
- Session History 按日期分组（今天 / 昨天 / 过去 7 天 / 更早），排序规则见 FR-NAV-003；
- Session 列表项为：CLI 单色标识（CX / CC）+ 标题 + 右侧状态点（P-D）；
- 左侧导航可折叠：折叠按钮位于顶栏左侧、窗口控制按钮之后，位置参考 ChatGPT；折叠后导航完全隐藏，顶栏保留展开按钮与 New Chat 按钮；
- 折叠时如当前 Project 存在 Needs Input、Error 或 Completed Unread Session，展开按钮显示单个状态点，优先级同 Project Tab 注意力点；
- 折叠状态为窗口级偏好，切换 Project 时保持不变；
- 悬停列表项时显示“⋯”菜单，Rename 从菜单触发并在原位编辑；
- Project View Mode 下只高亮当前 View，左侧 Conversation 所用的 Session 不在 Session History 中重复高亮；
- 左下角固定“设置”入口，不随 Session History 滚动；导航折叠或位于启动页时，通过菜单栏“设置…”或 ⌘, 打开设置（FR-SET-001）。

### Main Canvas

Session Mode：

以 Conversation 为绝对主体。

Project View Mode：

Conversation 与 Preview 左右并列。

布局比例在 UI 高保真阶段确定。

### Context Panel

要求：

- 支持展开/收起；
- Files / Search / Diff / Browser / Terminal 统一入口；
- 用户手动切换；
- 不抢占 Main Canvas 主视觉层级。
