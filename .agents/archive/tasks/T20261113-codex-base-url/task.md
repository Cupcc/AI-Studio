# Codex 自定义连接的地址不带 /v1 时的处理

## 目标

用户按网关首页的地址填写 Codex 的 Base URL 时，连接测试失败且提示看不出原因。来源：2026-11-13 在虚拟机里做真实 CLI 验证时发现，见[验证记录](../T20261113-vm-ui-checks/task.md#真实-cli-验证2026-11-13main-agent)。

## 现状

- Codex 的连接测试请求 `<地址>/responses`。地址不带 `/v1` 时，请求落到网关的管理页面，返回 200 和 HTML，应用提示“API 请求失败、超时或响应无效，请检查地址、网络和代理”。
- Claude Code 的连接测试先去掉末尾的 `/v1` 再请求 `/v1/messages`，所以带不带都能通过。
- 行为由[设置规格的 CLI 连接配置](../../../../specs/settings/spec.md#cli-连接配置2026-11-08-确认)第 1、4 条负责，改动属于用户可见行为。

## 技术决定

AI 决定，2026-11-13：

- 只在地址不含路径时补 `/v1`，比推荐答案的字面范围窄。`https://host/api/v3` 这类已含路径的地址原样使用。理由：用户写出的路径是有意填写的，对它补 `/v1` 会让 API 不在 `/v1` 下的服务无法填写，而且没有办法绕开；不含路径的地址正是本任务发现的情形。代价：API 在 `<路径>/v1` 下而用户只填了 `<路径>` 时，仍会看到原来的失败提示。用户可以改为“末尾不是 `/v1` 一律补上”。
- 补全放在地址校验里，保存和读取都经过它。连接测试、新建 Session 和已有 Session 的快照得到同一个地址，保存后表单显示补全的地址。连接测试与 Codex 启动参数的代码不需要改。
- 已知限制：API 直接在根路径下（`<地址>/responses`）的服务不能再用不含路径的地址表示。没有见到这样的服务，不为它加开关。

## 范围

- 做：按决定修改 Codex 地址的保存与读取，更新规格。
- 不做：不改 Claude Code 的处理，不改连接表单的结构。

## 验证（2026-11-13，Main Agent）

在本机虚拟机里用真实 CLI 验证，基线是提交 `850bd95`，命令是 `node scripts/vm-ui.mjs start --real`。Codex 为 `ci.yml` 固定的版本，网关地址和 Key 用占位符取自主目录的本地配置，不写入本记录。

- 表单：在“设置 → CLI → 配置 → 自定义连接”填入不含路径的网关地址并保存。保存前地址的路径是 `/`，状态为“未保存”；保存后表单里的地址以 `/v1` 结尾，状态为“已保存”，Key 显示“已安全保存”。
- 连接测试：显示“连接正常”，2.7 秒，模型 `gpt-6.1-sol`，回复“Hi! How can I help?”。修改前同一地址提示“API 请求失败、超时或响应无效”。
- 真实会话：新建对话后 Codex 在 4 秒内回复“8 乘 7 等于 56。”（[截图](evidence/codex-session-no-path.png)）。
- 单测：不含路径的 Codex 地址在保存、读取旧记录和读取 Session 快照时都得到 `/v1`；已含路径的地址和 Claude Code 的地址不变。
- 目录选择框用 `open-project` 注入固定返回值，其余操作都从界面入口执行。
- 没有验证：已含路径但缺 `/v1` 的地址（按技术决定不处理）；升级前已存在的真实数据库记录（由单测覆盖旧记录的读取）。
