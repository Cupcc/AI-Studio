## 1. 项目背景

随着 Codex CLI、Claude Code 等 AI Coding Agent 的成熟，开发者的软件开发方式正在由“人工操作 IDE 完成编码”逐渐转变为“通过自然语言驱动 Agent 完成开发”。

现有工具分别解决了部分问题：

- ChatGPT 提供了优秀的对话交互体验，但缺少对本地工程、CLI Agent、多 Session、代码变更和项目状态的系统管理能力；
- Codex CLI、Claude Code 等 CLI Agent 可以直接操作本地工程，但多项目、多 Session 和执行状态管理不够直观；
- Cursor 等 AI IDE 具备完整工程能力，但继承了传统 IDE 的复杂界面和较高的信息密度，对于以 AI Agent 为主要开发方式的用户而言较为厚重。

因此，本项目计划开发一款以 **本地项目为核心、AI 对话为主要交互方式、CLI Agent 为执行引擎** 的轻量桌面开发工作台。

产品重点不是重新实现完整 IDE，而是解决以下问题：

1. 统一管理多个本地开发项目；
2. 统一管理 Codex CLI、Claude Code 等 CLI Conversation Session；
3. 清晰呈现各 Session 当前是否运行、是否等待用户、是否刚刚完成；
4. 通过 AI 生成的 Project View 帮助用户理解项目进度、架构、Agent 分工和业务流程；
5. 在需要时提供 Files、Diff、Browser、Terminal 等工程工具，但避免默认占据大量界面空间。

## 2. 产品定位

### 产品定义

本产品是一款面向 AI 开发者和独立开发者的桌面 AI 开发工作台。

核心产品模型为：

**Local Project + CLI Session + AI Conversation + Project Knowledge + Project View**

用户通过对话向 Codex CLI、Claude Code 等 Agent 提出需求，由 Agent 直接操作本地工程；客户端负责组织项目、Session、项目知识及工程工具，并提供统一的可视化工作环境。

---

### 一句话定位

**以本地项目为中心，统一管理 Codex、Claude Code 等 CLI Agent Session，并通过 AI 动态项目视图帮助开发者完成开发和持续理解项目状态的轻量 AI Developer Studio。**

---

### 产品设计方向

整体产品体验要求：

- 视觉风格参考 ChatGPT Desktop 与 OpenDesign；
- 工程能力参考 Cursor，但避免复制传统 IDE 的复杂布局；
- 默认白色主题；
- 强调安静、高级、专业、轻量和低视觉噪音；
- AI Conversation 为主要交互入口；
- 工程能力按需展开，而非默认全部展示。

设计倾向可概括为：

| 参考方向 | 比例 |
|---|---:|
| ChatGPT 的视觉及交互轻量感 | 60% |
| OpenDesign 的 Workspace 工作方式 | 25% |
| Cursor 的工程工具能力 | 15% |

## 3. V1 产品目标

### V1 核心目标

V1 需要实现以下核心能力：

1. 用户可以将一个本地目录作为 Project 打开；
2. 用户可以同时打开并快速切换多个 Project；
3. 每个 Project 可以创建多个独立 CLI Session；
4. 每个 Session 与一个真实的 CLI Conversation Session 一一对应；
5. 支持 Codex CLI、Claude Code CLI；
6. 多个 Session 可以同时执行；
7. 用户可以清晰判断：
   - 哪些 Session 正在执行；
   - 哪些 Session 等待用户输入；
   - 哪些 Session 刚完成一轮工作；
   - 哪些 Session 出现异常；
8. 提供 Overview、Progress、Architecture、Agent Team、Business Flow 五类默认 Project View；
9. Project View 支持由 AI 动态生成和修改；
10. Project View 中可以直接通过普通 CLI Session 与 Agent 对话；
11. 提供 Files、Diff、Browser、Terminal 四类工程辅助工具；
12. 保持界面结构简单，不演变成传统重型 IDE。

## 4. V1 非目标范围

以下能力不属于 V1 MVP 核心范围：

- Jira 式任务管理；
- Epic / Story / Sprint / Ticket；
- 完整 Multi-Agent Orchestration；
- 客户端自定义 Agent Profile 系统；
- 完整 IDE Debugger；
- VS Code Extension 生态；
- 完整 Source Control 工作台；
- Problems / Outline 等传统 IDE 面板；
- 跨 Project 的统一 Attention Inbox；
- 自动 Worktree / Branch Agent 隔离；
- 多人实时协作；
- 企业级权限和组织管理。

上述能力可在后续版本评估。

## 5. 目标用户

### 核心用户

#### AI 开发者

特征：

- 已经使用 Codex CLI、Claude Code 等 Agent；
- 大部分编码工作通过 AI 完成；
- 需要同时处理多个 AI Conversation；
- 更关注任务结果、Diff 和运行状态，而不是持续手工编辑代码。

#### 独立开发者

特征：

- 一人维护多个产品或项目；
- 同时承担产品、开发、测试和发布等职责；
- 需要快速掌握项目整体状态；
- 不希望额外维护复杂项目管理系统；
- 希望 AI 自动整理项目进度、架构及业务状态。

## 6. 核心使用场景

### 打开已有项目

用户选择一个本地代码目录，将其作为 Project 打开。

系统恢复该 Project 上一次使用状态，包括：

- 上一次打开的 Session 或 Project View；
- 已打开的右侧工具面板；
- 当前界面布局状态。

首次打开 Project 时进入 Overview。

---

### 创建新的开发对话

用户点击 New Chat，进入新对话草稿。

用户发送第一条消息时，系统使用该 Project 的默认 CLI 创建新的 CLI Conversation Session，CLI Agent 在当前本地 Project 中执行。

新 Session 创建后立即进入左侧 Session History；未发送消息的草稿不创建 Session（FR-CHAT-001；UX Specification 第 10 节 D-01；2026-10-09 确认）。

---

### 多 Session 并行开发

同一 Project 中可以同时存在多个 Session，例如：

- Codex 正在开发支付模块；
- Claude Code 正在修复 OAuth；
- Codex 正在运行测试。

用户通过左侧 Session 状态快速判断各 Agent 当前情况。

---

### 查看 Agent 完成结果

某个 Session 完成当前一轮工作后：

- Session History 中出现绿色完成提醒；
- 用户无需停留在该 Session；
- 可以继续操作其他 Session；
- 点击已完成 Session 后直接进入对话最新位置；
- 点击后绿色提醒消失。

---

### 查看项目架构并要求 AI 修改

用户点击 Architecture。

Main Canvas 进入 Project View Mode：

- 左侧显示 Conversation；
- 右侧显示 Architecture Preview。

用户可以直接输入：

“把支付模块拆分成 Billing Service 和 Webhook Service。”

该请求仍通过普通 Codex / Claude Code Session 执行。

AI 可以同时：

- 修改 Project Knowledge；
- 更新 Architecture View；
- 根据用户要求进一步修改真实代码。

---

### 查看代码修改

用户手动打开右侧 Diff。

查看当前 Agent 对本地项目产生的文件变更。

AI 不主动改变用户当前 Workspace 布局。

## 7. 核心概念定义

### Project

V1 中：

**Workspace = Project。**

不额外设置 Workspace → Project 两级关系。

一个 Project 对应一个本地文件目录。

示例：

`~/Projects/my-saas`

Project 是以下内容的容器：

- 本地源码；
- CLI Session；
- Project Knowledge；
- Project Views；
- UI 状态；
- 工具状态。

---

### Session

一个客户端 Session 对应：

**一个真实 CLI Conversation Session。**

关系必须保持：

`App Session 1 : 1 CLI Conversation Session`

Session 不是 Task。

一个 Session 内用户可以连续完成多个不同任务。

是否继续当前 Session 或创建 New Chat，由用户自行决定。

---

### CLI

V1 支持：

- Codex CLI；
- Claude Code CLI。

创建 Session 时确定 CLI。

Session 创建后：

**不可在 Codex CLI 与 Claude Code CLI 之间切换。**

在底层 CLI 本身支持的情况下，可以在同一个 Session 中切换模型。

---

### Project View

Project View 是项目知识的可视化页面。

V1 默认提供：

- Overview；
- Progress；
- Architecture；
- Agent Team；
- Business Flow。

Project View 不是固定 Dashboard，也不是特殊 Session。

其核心形式为：

**Project Knowledge → Structured Data → View Rendering → AI Generated UI**

V1 中的 “AI Generated UI” 指 Agent 在客户端提供的受信组件范围内声明式设计 View，不生成可执行的 HTML / JavaScript；自由 HTML 推迟到 P1 / 自定义 View（[DEC-05](<07. Decisions.md>)，2026-10-09 确认）。

---

### Project Knowledge

Project Knowledge 表示 AI 对项目高层结构化认知。

包括但不限于：

- 项目进度；
- 系统架构；
- 业务流程；
- Agent 分工；
- 项目概况；
- 用户后续新增的知识视图。

Project Knowledge 与最终 HTML/UI 展示必须分离。

## 8. 已确认的产品原则

以下原则作为 V1 产品设计和研发决策的约束条件：

1. Project 是一级核心对象；
2. Workspace 与 Project 不重复建模；
3. 一个 Project 对应一个本地目录；
4. Session 与 CLI Conversation 一一对应；
5. Session 不是 Task；
6. UI 不增加 Run 概念；
7. 一个 Session 固定一个 CLI；
8. Session 内可以按照 CLI 原生能力切换 Model；
9. 多 Session 可以同时执行；
10. 历史 Session 无事件时不显示 Idle；
11. 一轮 Agent 完成后显示 Completed Unread 提醒；
12. 点击 Session 即视为已查看结果；
13. Project View 本质是 Project Knowledge 的可视化；
14. Project View 的数据与展示必须分离；
15. Project View 不绑定唯一长期 Session；
16. Project View 内的 Conversation 仍是普通 CLI Session；
17. New Chat 创建的所有 Session 都必须出现在 Session History；
18. Project View 使用“左 Conversation、右 Preview”布局；
19. 客户端不自研 Agent Profile 系统；
20. 优先复用 CLI 原生 Agent、Skill、Rule 和 Context 能力；
21. Context Panel 由用户主动控制；
22. AI 不主动改变 Workspace Layout；
23. V1 保持白色、安静、专业、低视觉噪音的视觉方向。

## 9. 产品成功标准

V1 成功的核心不是“提供最多开发功能”，而是用户能够明显感受到：

1. 比直接打开多个 Terminal 更容易管理 CLI Agent；
2. 比传统 IDE 更轻、更容易保持注意力；
3. 能够快速知道哪个 Agent 正在工作、哪个需要自己介入；
4. 能够从 Project View 快速恢复对项目整体的理解；
5. Conversation、代码执行、项目知识和工程工具之间形成一个完整工作闭环。

最终体验应接近：

> **开发者负责目标、判断和决策，CLI Agent 负责执行，客户端负责组织项目、呈现上下文和管理注意力。**
