## 2. 技术设计约束

> 本文档由 V1.0 原始 PRD 重组而来。除文档治理、交叉引用和追踪关系外，不新增产品需求；如与 Product Definition 或 Functional Requirements 冲突，以文档索引定义的优先级为准。

技术方案必须服从 Product Definition 与 Functional Requirements，不得通过实现便利改变以下产品语义：

- Project 是一级核心对象，Workspace 与 Project 不重复建模；
- 一个 Project 对应一个本地目录；
- App Session 与真实 CLI Conversation Session 保持 1:1；
- Session 不是 Task，UI 不引入 Run 作为主要用户概念；
- 一个 Session 固定一个 CLI；
- 多 Session 可以并行；
- Project Knowledge 与最终 View 展示必须分离；
- 客户端不自研 Agent Profile Framework，优先复用 CLI 原生能力。


## 3. V1 推荐技术栈

V1 采用 **Electron + React + TypeScript** 作为跨平台桌面客户端技术栈。该选择服务于本产品的本地项目管理、CLI 进程管理、内嵌 Browser、Terminal 和流式 Conversation 要求。

### 分层边界

客户端分为四个逻辑层：

1. **Renderer UI**：只负责界面呈现和用户交互，不直接访问文件系统、Shell 或凭据；
2. **Preload Bridge**：通过最小化、类型化的 IPC API 暴露受控能力；
3. **Application Services**：负责 Project、Session、View、Knowledge 和工具状态；
4. **Runtime Services**：负责 CLI 子进程、PTY、文件系统、Git 和 Browser 实例。

CLI Agent、用户 Terminal 和 Browser Preview 必须使用独立的进程或渲染上下文。任何由 AI 生成的 HTML / JavaScript 都不得直接获得 Node.js、文件系统或完整 IPC 权限。

### 工程工具实现原则

保留本节工具技术栈，采用文件树惰性加载和文件事件合并刷新；工具服务与 Renderer 面板的挂载 / 卸载分离。PTY 及输出状态由 Project 级服务持有，本轮补丁按 Session / 原生 Thread / Turn 保存（2026-10-12 确认，[DEC-10](<07. Decisions.md#dec-10-工程工具实现原则>)）。

Browser 使用主进程管理的 WebContentsView，禁用网页 Node 和应用 Preload；导航、权限、新窗口、下载及可见性各自通过受控处理器管理。Monaco 双文本 Diff 需要对应两侧内容，只有原生 patch 时保留 patch 展示，不以当前工作区伪造历史原文。Git 查询需另行包含未跟踪文件，特殊路径、无 HEAD、二进制和大文件的降级须验证。接口与生命周期细则由 [工具规格](../specs/tools/spec.md) 负责。

参考产品的页面标注、行内评论、服务器管理和自动化能力仅作为后续设计资料。Browser 首轮边界已于 2026-10-13 确认，见 FR-TOOL-003 与工具规格 TOOLS-Q1、Q5、Q6；分别处理顶层导航 / 重定向 / 新窗口、权限、下载和外部打开，不用关闭 webSecurity 绕过限制。Project 独立内存分区与地址持久化分离，弹层期间处理嵌入视图遮挡与焦点。

文件引用与原生轮次补丁的跨模块契约、终端重新附着及 Browser 命令归 [工具规格 §4](../specs/tools/spec.md#4-状态与接口) 维护（DEC-14，2026-10-13 确认准备方向；技术细化待实现验证）。轮次记录须保留来源、身份、可用状态和原始 patch；未知、明确为空、接口不提供与失败不能混同。真实 CLI 补丁能力继续按事项 13 验证，不以在线文档或类型定义充当当前版本的运行证据。

Electron 是 V1 的确认选型。Tauri 2 不作为 V1 主线框架；后续只有在安装包体积或资源占用成为明确约束时，才重新进行替代方案评估。

### 外部桌面端参考与开源边界

技术实现可以参考 ChatGPT Desktop、Claude Desktop 和 Codex App 的公开交互与产品行为，包括项目导航、并行 Session、流式 Conversation、权限确认、后台任务、变更审阅和恢复反馈。这些产品只作为交互与架构参考，不作为本项目的源码、私有协议或运行时依赖；复制代码、资源或协议前必须单独核对其许可证与公开授权范围。

Codex 的开源边界需明确区分：截至 2026-10-11，OpenAI 官方公开说明 Codex CLI、App Server 和官方 Codex SDK 为开源组件；Codex App 是基于开放 Codex harness 的桌面产品，且使用开源、可配置的系统级沙箱，但这不等同于 Codex Desktop 完整应用（尤其是桌面 UI 和产品服务）整体开源。

V1 的 Codex 集成边界是客户端机器上已安装的 **Codex CLI**：客户端负责发现、启动、通信、停止和恢复本机 CLI 进程，不直接集成 Codex Desktop，也不把远程 Codex 服务或 API 作为本产品的直接运行时依赖。Codex CLI 暴露的 App Server stdio 是本地进程的协议入口；官方 Codex SDK 仅作为实现调研参考，不作为 V1 必需依赖。客户端继续通过 `AgentProvider` / Adapter 隔离 Codex CLI 与 Claude Code CLI 的实现细节；Claude Desktop 同理只按公开资料和可验证行为参考，不假定其内部实现开源。

### 开发前 CLI 校验

2026-10-08 已在 macOS arm64 完成真实 CLI 验证，见 [CLI Integration Preflight](../tasks/T20261008-cli-preflight/report.md)。客户端启动本机 Codex CLI 的 App Server stdio 协议；Claude Code 使用官方 Agent SDK Streaming Input 驱动已安装 CLI。创建、流式输出、同一原生 Session 恢复、授权 / 问题作答及并行运行均已验证。

Codex 0.161.0 的 `turn/interrupt` 用于中断当前回合，Unified Exec 会保留后台命令。先前三次“收到 `interrupted` 后测试子进程仍存活”的观察保留，但不能仅凭该行为判定 Codex 进程终止缺陷。补充源码核对与真实调用已验证 `thread/backgroundTerminals/clean` 和 `thread/backgroundTerminals/terminate`：测试进程退出，同一 Runtime 中另一 Thread 继续执行，原 Thread 保留上下文并可继续对话。正常 Stop 应优先使用原生进程清理；终止独立 Runtime 后恢复同一 Session 作为清理失败或接口不可用时的兜底路径，详见校验报告第 4、5 节。

首阶段仍建议每个活动 Session 使用独立 Runtime，以隔离崩溃和 Runtime 终止兜底。原生清理在共享 Runtime 中的 Thread 隔离已验证，独立 Runtime 并非正常 Stop 的接口前提；若采用共享 Runtime，须证明兜底也不会影响其他 Session（FR-SESSION-003）。

CLI Adapter 需要关联用户主动取消与原生终态：本次 Claude 主动取消返回 `error_during_execution`，不能仅凭该类型标为 Error。具体映射及剩余校验见校验报告第 5、6 节。

## 5. User Terminal 与 Agent Runtime 隔离

用户 Terminal 与 CLI Agent 自身使用的 Runtime / PTY 必须逻辑分离。

原因：

- 防止 cwd 互相影响；
- 防止 Agent 修改用户 Shell 状态；
- 防止 Agent 意外终止用户进程；
- 保持运行状态可预测。

Terminal 实例按 Project 管理，每个 Terminal Tab 使用独立 PTY；面板可见性和当前 Session 的切换不得触发进程销毁。多实例交互范围以 FR-TOOL-004 为准（2026-10-10 确认；[DEC-09](<07. Decisions.md#dec-09-project-内的-terminal-tabs>)）。

Project 关闭 / 退出应用由可信主进程分别编排 Session 停止与用户 PTY 清理；确认范围按 FR-PROJ-002 纳入全部未退出终端。不能扩张 Session Stop 的清理范围来代替工具资源释放；未完成清理时保留诊断、重试与所属 Project 入口。屏幕模型、有界缓存、输出背压及快照 / 增量交接按工具规格 §4.3 实现并验证（2026-10-13 确认，DEC-14）。

### Codex Stop 实现约束

以下约束用于实现输入区的 Stop（FR-INPUT-001）和多 Session 隔离（FR-SESSION-003），不新增 UI 状态或独立 Run / Task 概念。

1. Stop 时暂停该 Session 的新任务提交，记录用户取消意图，发送 `turn/interrupt` 并处理对应回合终态；不能收到 `interrupted` 就宣告资源清理完成。
2. 优先复用原生后台命令接口。初始化时开启 `capabilities.experimentalApi: true`；这些接口为实验性能力，应锁定支持的 CLI 版本与生成的协议类型，并处理接口不可用的情况。
3. 停止本轮命令时，关联 `threadId`、`turnId`、`itemId` 与 App Server `processId`，使用 `thread/backgroundTerminals/terminate` 精确终止目标。`processId` 是 App Server 内部编号，不是系统 PID。本轮归属映射和保留先前后台服务的行为仍需正式 Adapter 验证。
4. `thread/backgroundTerminals/clean` 清理该 Thread 全部后台命令，包括先前回合启动的服务；仅在清理范围明确包含这些命令时使用。不得用清理整个 Thread 的操作隐式替代本轮命令终止。
5. Stop 完成须同时确认回合结束和目标命令退出。`clean` 的空响应仅表示请求已提交，后台列表清空也不能单独证明系统进程已退出；Process Manager 需获取退出证据，并为清理设定有限等待时间。
6. 清理超时、失败或接口不可用时，可终止该 Session 的独立 Runtime，确认所属进程清理后，再以原 `thread.id`、cwd 和配置恢复。该兜底可能停止同一 Session 先前启动的后台命令，不能承诺保留这些服务；范围与恢复行为须纳入 Adapter 校验。
7. 任何清理或恢复都不得终止其他 Session、Project 或用户 Terminal。清理失败时不得并行启动新旧 Runtime；恢复失败时不得静默创建新 Session，也不得自动重跑已取消的命令。

### 退出与异常清理责任边界

依据用户 2026-10-11 对话「accept all,update docs」确认（DEC-11）；本次 diff 待审阅：

- 正常退出：在有限等待内对客户端启动并可确认归属的 Runtime 及受管子进程执行清理，核对退出结果；失败或无法确认时保留并报告诊断，不宣称清理成功。既有 Stop 的目标命令退出证明要求不变。
- 异常退出：不承诺崩溃、强制终止等任何情况下即时零残留。再次启动时按进程归属记录检查，仅在确认原宿主已失效且进程身份仍匹配时清理；具体方案与验证由 Adapter A-Q3 承接。
- 不因进程曾被 CLI 使用就视为客户端所有；共享 MCP、非客户端受管的外部服务、其他活跃实例、其他 Session / Project、用户终端及归属不明进程不得被误清理。无法确认归属时保留诊断，不扩大终止范围。
- 本节限定清理职责和保证，不把未完成的受管进程清理实现或验证从交付要求中移除，也不改变原生 CLI 的执行策略。

- 用户更新；
- View Rendering；
- 后续自定义 View。

## 7. 非功能需求

### 性能

- Project 切换应保持即时响应；
- 大量历史 Session 不应导致左侧列表明显卡顿；
- 多 CLI Session 并行不得阻塞主 UI；
- Agent 输出必须支持流式展示。

---

### 稳定性

单个 Session CLI 进程失败：

不得导致：

- Application 崩溃；
- 其他 Session 中断；
- 其他 Project 中断。

---

### 本地性

V1 以本地开发工程为核心。

客户端必须正确处理：

- 本地文件读写；
- 本地 Shell；
- CLI Process；
- Project Directory；
- Localhost Preview。

---

### 可扩展性

CLI Integration 不应硬编码为只有两个永久实现。

架构上需为未来新增其他 CLI Agent 留出 Adapter 能力。

但 V1 实际交付范围：

- Codex CLI；
- Claude Code CLI。

## 8. 技术设计阶段交付物

后续技术设计应至少覆盖：

- CLI Adapter Architecture；
- Session Manager；
- Process Manager；
- Project Manager；
- [Project Knowledge](../specs/project-view/spec.md)；
- [View Renderer](../specs/project-view/spec.md)；
- [Context 工程工具](../specs/tools/spec.md)（Files / Diff / Terminal / Browser Preview）；
- Local Persistence。

这些交付物用于回答“如何实现”，不能替代 Functional Requirements 中的产品行为定义。
