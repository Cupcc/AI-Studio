## 1. 验收使用原则

- 本文件的 AC 是 **V1 核心端到端验收场景**，不是对全部 FR 的逐条测试用例全集。
- 每个实现任务应引用对应 FR；测试用例可在核心 AC 基础上继续细化边界、异常和平台兼容场景。
- 如 AC 与 FR 描述不一致，应先修正规格，不应由测试阶段自行改变产品语义。
- 验证分工、任务收尾与人工功能 / 阶段验收按 [Task Protocol](../tasks/README.md#acceptance) 执行；本文件只定义产品预期，task 完成不代表对应 AC 已通过或产品已获人工验收（2026-10-11 确认，治理规则 diff 待审阅）。
- V1 首发验收平台为 macOS 13 Ventura 或更高版本、Apple Silicon arm64；Intel / x64、Windows / Linux 不在 V1 首发验收范围（2026-10-17 确认，见 [DEC-15](<07. Decisions.md#dec-15-v1-macos-arm64-兼容范围>)）。2026-10-08 的 [CLI 开发前校验](../tasks/T20261008-cli-preflight/report.md)提供 Adapter 实现输入，不替代本文件的端到端验收。
- 当前 V1 的真实 CLI 验收只覆盖 Codex；Claude Code 的实现、模拟验证和历史真实证据保留，但本轮不新增真实调用、不把其真实链路记为通过。AC 原有的双 CLI 产品预期仍保留，待后续独立验收（2026-10-18 确认，见 [DEC-16](<07. Decisions.md#dec-16-v1-真实-cli-验收范围>)）。2026-10-26 起 Adapter 层的 Claude 真实验证按用户指示重新开始，范围与结果见[适配任务](../tasks/archive/T20261026-claude-adapt/task.md)，不改变本条的 V1 验收范围，也不把任何 AC 记为通过。
- Codex 的模型访问、额度、限流以及发生限流后的停止或错误由 Codex CLI / 上游服务提供方决定；应用只传递请求、接收结果和展示状态，不设置调用次数、费用上限、自动重试、自动换模型或截断护栏。用户显式选择的模型仍按输入规格传给 CLI。真实结果按 CLI 实际行为记录。
- V1 不设固定上线日期；目标版本为 `v1.0.0`，发布渠道为 GitHub Releases。后续发布准备仅生成产物、暂不发布；本轮只更新文档（2026-10-18 确认，见 [DEC-17](<07. Decisions.md#dec-17-github-release-发布渠道与排期>)、[DEC-21](<07. Decisions.md#dec-21-v1-github-release-版本号>)、[DEC-22](<07. Decisions.md#dec-22-发布准备范围与本轮文档边界>)）。
- 人工体验结论及接受范围见[总体验收的人工功能验收](../tasks/archive/T20261009-v1-foundation-slice/acceptance.md#人工功能验收)；2026-10-18 用户已确认路线图所列现有功能的人工体验全部通过。技术验证及未实现范围仍按各任务证据跟踪。

## 2. V1 核心验收场景

### AC-01 多项目

用户同时打开三个本地项目。

能够通过顶部 Project Tabs 快速切换。

三个 Project 的：

- Session；
- Project View；
- Context Panel 状态；

保持独立。

---

### AC-02 创建 Codex Session

用户在 Project A 创建 Codex New Chat。

输入需求后：

- Codex 正常开始执行；
- Session 出现在左侧；
- 显示 Running；
- Conversation 流式输出。

---

### AC-03 并发执行

用户在同一 Project 创建：

- 一个 Codex Session；
- 一个 Claude Code Session。

两个 Session 可以同时执行。

切换 Session 不应打断后台执行。

当前 V1 真实验收先验证 Codex 多 Session 并发；Claude Code 的真实并发验收暂缓，不改变原有双 CLI 产品预期。

---

### AC-04 完成提醒

用户正在 Session B。

Session A 在后台完成。

结果：

- Session A 出现绿色圆点；
- 用户点击 Session A；
- 页面直接显示最新 Conversation；
- 绿色圆点消失。

---

### AC-05 Needs Input

后台 Agent 需要用户做决定。

Session History 中必须出现明显 Needs Input 状态。

用户点击后可以直接看到 Agent 当前等待内容。

---

### AC-06 Project View

用户打开 Architecture。

页面显示：

- 左侧 Conversation；
- 右侧 Architecture Preview。

用户输入：

“重新整理支付模块架构。”

系统可以通过普通 CLI Session 处理请求，并更新 Architecture Preview。

---

### AC-07 工具面板

用户可以分别打开：

- Files；
- Diff；
- Browser；
- Terminal。

关闭后 Main Canvas 恢复空间。

Agent 不得自行强制打开这些 Panel。

依据 FR-TOOL-002、FR-TOOL-004 的 2026-10-10 确认，补充工具内容验收：

- Project Diff 覆盖相对 HEAD 的已暂存、未暂存和未跟踪文件，支持 M / A / D、文件列表和单文件 Diff；不提供 MVP 范围外的 Git 操作界面。
- 从完成行打开本轮原生 Diff，明确显示范围；保存后的补丁不随后续工作区修改而改变。覆盖多 Session 并行，不能混入其他轮次记录。
- 原生数据不可用时按 FR-TOOL-002 显示降级入口；非 Git 项目显示说明与指引，不自动初始化或创建快照。CLI 能力与覆盖边界须记录验证结果（04 第 1 节第 13 项）。
- 同一 Project 可同时运行至少两个独立 Terminal 实例（如开发服务器与测试命令），支持新建、切换、关闭；切换 Session / Project、隐藏面板和 Session Stop 均不终止用户终端。关闭一个实例不影响其他终端或 Agent Runtime。

依据 2026-10-12 确认的 DEC-10 及 FR-TOOL-001～004，补充以下验证：

- Files 展开目录和查看文件按需读取；增删 / 更新后的树与文件内容正确，有效的展开和选择保持，查看不自动附加上下文。
- 历史轮次只有 patch 时仍按保存内容显示；不能用当前文件伪造历史两侧内容。未跟踪文件、特殊文件名、无 HEAD、二进制及大文件按工具规格验证对应内容或明确降级。
- Browser 实际打开 localhost；网页无法访问应用 Node / IPC。工具切换、Project 切换及窗口 resize 后没有页面遮挡当前内容，加载失败能反馈，关闭所属 Project 后释放实例。
- Terminal 面板被隐藏 / 卸载后重新显示时，进程和屏幕 / 输出状态可继续使用。关闭确认、取消和最后一个 Tab 的空状态按 [工具规格](../specs/tools/spec.md#fr-tool-004-terminal) 验证；清理隔离遵循 04 第 5 节。

本轮范围澄清不新增 AC 编号（2026-10-11 确认；DEC-11）：AC-03 的并行验证不包含文件冲突检测或自动 Worktree 隔离；AC-06 按 FR-VIEW-003 由用户通过普通 Session 发起生成；AC-07 按 FR-TOOL-002 区分项目变更与原生轮次记录，不以全量 Agent 归因为验收目标。

2026-10-13 确认补充（DEC-14；关联 AC-01、FR-PROJ-002、FR-INPUT-001）：

- Files → 标签 → Session → Adapter 端到端验证 Codex 实际收到文件引用；覆盖普通发送及 Codex 原生支持的运行中追加、文件消失及提交失败，不以标签可见作为链路通过。Claude Code 的真实文件接收暂缓，保留为后续独立验收。
- Browser（首轮历史范围，当前导航 / 存储按下方 DEC-25 补充验收）验证 localhost / 回环地址、外站导航 / 重定向 / 新窗口提示及取消、Project 分区隔离；应用重启后保留地址、默认不恢复登录数据。一般外站内嵌、可选持久化与新增 Agent 页面自动化不属于首轮承诺，原生 CLI 接入要求不变。
- 仅有 Terminal 存活、Session 与 Terminal 并存以及终端停在 Shell 提示符时，关闭 Project / 退出应用均按 FR-PROJ-002 合并确认；取消不清理，失败保留诊断及重试，不影响其他 Project 或不属本应用的资源。
- 补丁记录验证未知 / 明确为空 / 不可用 / 失败、重复更新与迟到事件、重启恢复及后续工作区变化；终端验证 ANSI / 光标、resize、大量输出与隐藏后重新附着。

2026-10-26 确认补充（DEC-25；FR-TOOL-001～005）：

- Files 右键完成新建、重命名、复制粘贴、拖拽移动和删除到废纸篓，`.git` 与 Project 外路径不可操作；⌘P 快速打开、Git 状态着色、用 VS Code / 默认应用打开及 Markdown / 图片预览可用；仍不提供应用内编辑。
- Search 在 Project 内搜索文本 / 正则，遵守 .gitignore，结果点击后在 Files 定位到行；上限与超时明确提示。
- Diff 保持只读，可切换列表 / 树、并排 / 行内、上一处 / 下一处变更与折叠未改动区域。
- Terminal 链接、查找、清屏、重命名与右键菜单可用；第 3 步验证分屏后隐藏 / 重新显示不丢输出。
- Browser 打开本地与外部 http / https 网址并自动补协议；后退 / 前进 / 停止 / DevTools / 系统浏览器打开可用；浏览数据跨 Project 共享并在重启后保留，清除后失效；网页仍无法访问应用 Node / IPC。上一段中“一般外站内嵌、可选持久化不属于首轮承诺”及“默认不恢复登录数据”的验收要求由本段取代。

场景与验证方式见[本轮任务](../tasks/archive/T20261026-tools-vscode-parity/task.md#验收标准)。

前置条件、操作、预期与证据计划见 [工程工具任务的验收场景](../tasks/archive/T20261009-context-tools/task.md#验收场景准备)。2026-10-13 文档准备时仅更新文档、未执行以上场景；其后 Terminal / Browser 运行时阶段已执行部分场景，结论与未覆盖范围见[运行时工具验收](../tasks/archive/T20261009-context-tools/acceptance.md)。Files / 项目 Diff 阶段以及 2026-10-18 Codex 原生引用、本轮 Diff / 轮次补丁的新增结果见同一验收记录；历史结论及其未覆盖项保持原范围和基线。DEC-25 新增范围的当前技术结论、未覆盖项与人工功能验收入口由[工具对齐独立验收](../tasks/archive/T20261026-tools-vscode-parity/acceptance.md)负责。
