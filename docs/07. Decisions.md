## 桌面端基础

### DEC-01 SQLite 驱动采用 `node:sqlite`

草稿 · 2026-10-09 · [T20261009-app-skeleton](../tasks/T20261009-app-skeleton/research.md) 第 3 节

- **决定**：主进程使用内置 `node:sqlite`。数据库位于应用 userData 目录，不写入 Project 目录；迁移只向前、幂等；其他模块只通过 `CoreServices` 访问数据库。文件名、迁移命名与用法见 [apps/desktop/README.md](../apps/desktop/README.md) 第 4 节。
- **理由**：`better-sqlite3` 需按 Electron ABI 重编译，且与 Vitest 使用的 Node ABI 冲突；内置驱动已在 Electron 主进程和打包冒烟中验证可用。
- **注意**：`node:sqlite` 在 Node 24 仍为实验性，升级 Electron 时需复跑数据库测试。

### DEC-02 进程边界与类型化 IPC

草稿 · 2026-10-09 · [T20261009-app-skeleton](../tasks/T20261009-app-skeleton/research.md) 第 2、5 节；用法见 [apps/desktop/README.md](../apps/desktop/README.md) 第 3 节

- **决定**：窗口开启 `contextIsolation`、`sandbox`，Renderer 经 `app://studio/` 加载并受严格 CSP 限制；默认拒绝新窗口、外部导航、`<webview>` 和权限请求。例外：新窗口请求中的 http(s) 链接交给系统浏览器打开，其余协议忽略；权限只对 Renderer 来源放行剪贴板写入（`clipboard-sanitized-write`），供代码块复制（2026-10-10，依据 Agent 回复 Markdown 渲染的确认，见 [T20261010-prototype-v02-alignment](../tasks/archive/T20261010-prototype-v02-alignment/task.md)）。每个功能声明一份 IPC 契约，Preload 按契约通用生成 `window.studio`，主进程处理器先校验输入再执行；契约与处理器各在登记文件中加一行。
- **理由**：满足 04 第 3 节“Preload 只暴露最小化、类型化 IPC”，并让并行 task 只在登记文件中各加一行。
- **放弃**：通用 `invoke(channel)`（任意通道可调用）、手写 Preload 桥接（易与契约不一致）、tRPC 类框架（当前不需要）。

### DEC-03 功能目录与写入范围

草稿 · 2026-10-09 · 目录结构见 [apps/desktop/README.md](../apps/desktop/README.md) 第 2 节

- **决定**：`apps/desktop` 按功能划分目录（契约、处理器、服务、Renderer 功能目录各归一个功能），功能之间不直接引用对方内部文件；共享登记文件每个功能只加一行；骨架文件的修改需在 task 中说明。
- **理由**：并行 task 的写入范围可以直接按功能路径划分，不互相冲突。

## Project View

以下四条已于 2026-10-09 确认：[T20261009-project-view](../tasks/archive/T20261009-project-view/task.md) 的 Q1～Q12 均采纳推荐答案。调研见同目录 `research.md`。

### DEC-04 Project Knowledge 存储

已确认（2026-10-09） · 04 第 1 节第 1、2 项 · Q1、Q2、Q6、Q11

- **决定**：存放在 Project 内隐藏目录 `.ai-studio/`：`knowledge/<view-id>.json` 存事实，`views/<view-id>.view.json` 存呈现（可选，缺失时用应用内置默认）。格式为带 `schemaVersion` 的 JSON，一个 View 一份文件。目录自带内容为 `*` 的 `.gitignore`，默认不进 Git。客户端只读取和校验，不修改 Knowledge。
- **理由**：Agent 能直接用 CLI 文件工具更新，无需自研写入工具（原则 19、20）；`.claude`、`.codex` 等目录受 CLI 保护，项目外目录需要扩大 Session 权限；分文件可减少并行 Session 的写入冲突。

### DEC-05 Project View 渲染

已确认（2026-10-09） · 04 第 1 节第 3 项 · Q3、Q4、Q5

- **决定**：V1 只实现声明式渲染：View Definition 是经 Schema 校验的 JSON，Agent 只能选择受信组件、布局和数据绑定，不能提供 HTML、脚本或任意 CSS。校验或渲染失败时保留上一次成功版本并显示错误。自由 HTML（无同源权限、禁网的沙箱 iframe）作为后续第二层，启用前需原型验证。
- **理由**：强制事实与展示分离（FR-VIEW-004），Agent 输出不会获得任何执行能力，关系图版式也更稳定。
- **取舍**：Agent 只能在组件词汇范围内设计 View。01、04 中“AI Generated UI / HTML”在 V1 按此理解，自由 HTML 推迟到 P1 / 自定义 View（Q3，2026-10-09 确认）。

### DEC-06 View Context 注入

已确认（2026-10-09） · 04 第 1 节第 10 项 · Q7、Q8、Q10、Q12

- **决定**：用户从 View 发起的第一条消息前，附加一个独立的英文文本块，只写当前 View、相关文件路径和少量编辑规则，不内联 Knowledge 内容；Codex 与 Claude 使用同一份文本。界面中显示为可移除的“当前 View”标签，移除后不注入，但仍记录 `origin_view_id`。
- **理由**：用户可见、可移除，两种 CLI 实现一致，且不修改用户的 AGENTS.md / CLAUDE.md。
- **放弃（V1）**：系统提示 / `developerInstructions`（用户不可见）、写入 AGENTS.md、打包 Skill 与 Claude hooks（留待 Adapter 稳定后评估）。

### DEC-07 Project View 刷新与权限

已确认（2026-10-09） · 04 第 1 节第 11 项 · Q9

- **决定**：客户端从不自动发起 AI 生成。Project 打开期间监视 `.ai-studio/`，并在打开 Project、回合结束、窗口重新获得焦点时补扫；读取、校验通过后推送给只读的 Preview。刷新不切换右侧当前内容；多步更新的中间错误延后提示。
- **理由**：满足 FR-VIEW-003（不自动生成）、FR-VIEW-006（无隐藏对话）和 D-06（保留上一次成功渲染），并保证 Agent 修改时 View 能实时更新。

### DEC-12 外观主题与设置

已确认（2026-10-12） · 用户对话「原型v03 和v04 都可以保留吗？ 作为 appearance theme」「添加设置功能模块，支持主题选择与切换」，随后选择默认毛玻璃、设置入口位于左下角并支持快捷打开、浓淡固定、降低透明度时显示白色；同日对提案回复「accept」，并要求颜色模式「默认跟随系统设置，也可以支持3种模式的选择」；本次 diff 待审阅。编号保留既有 DEC-10、DEC-11。

- **决定**：交互原型 v04 与 v03 分别作为毛玻璃（默认）与纯色两种主题保留，颜色模式默认跟随系统、可选浅色或深色，用户在新增的设置模块中选择；产品原则由 [01 第 8 节原则 23](<01. Product Definition.md#8-已确认的产品原则>) 负责，行为由 FR-SET-001、FR-SET-002 与 [settings spec](../specs/settings/spec.md) 负责。毛玻璃使用 macOS 原生窗口材质实现。
- **理由**：用户希望保留两种风格并自行选择；毛玻璃与 ChatGPT Desktop 的参考方向一致，白色保留原已确认的安静白底，满足偏好不同或开启“降低透明度”的用户。

- **取舍**：不做浓淡调节与自定义颜色；两种主题、两种模式共用布局与交互，仅颜色、材质和少量形状不同（胶囊 Tab、内容区边距），每次界面改动需在四种组合下检查颜色、在两种主题下检查布局。
- **落实**：[设置与外观任务](../tasks/archive/T20261012-settings-theme/task.md)。
